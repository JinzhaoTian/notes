
## Network Partition

网络分区（Network Partition）是分布式系统中一种关键的故障模式，指由于网络故障导致集群节点被分割成多个无法互相通信的子集，也称为"网络分裂"或"脑裂"情况。

**基本定义**

- 分布式系统的节点之间**网络连接中断**
- 导致集群被分割成**两个或多个独立子集**
- 各子集内部可以通信，但**子集之间完全无法通信**

**发生原因**

1. **物理层故障**
	- 网线/光纤损坏
	- 交换机/路由器故障
	- 电源故障导致网络设备宕机
2. **网络配置问题**
	- 错误的路由配置
	- 防火墙规则阻断
	- VLAN配置错误
3. **软件层问题**
	- 网络协议栈崩溃
	- 网卡驱动故障
	- 操作系统网络服务异常
4. **环境因素**
	- 数据中心间专线中断
	- 云服务商可用区(AZ)隔离
	- DDoS攻击导致网络拥塞


## Split-Brain

裂脑（Split-Brain）指的是在分布式系统或高可用集群中，由于网络分区（network partition）导致集群成员之间无法通信，进而使不同部分的节点都认为自己是唯一存活的节点，从而形成多个独立运行的"脑"（决策中心）。

### 解决方案

1. 仲裁机制（Quorum）
	- 要求任何决策必须获得多数节点同意
	- 例如在 3 节点集群中，至少需要 2 个节点达成一致
	- 确保网络分区时最多只有一个子集能形成多数派

2. 隔离（Fencing）机制
	- **资源级隔离**：使用 STONITH（Shoot The Other Node In The Head）强制关闭被认为失效的节点
	- **存储隔离**：使用 SCSI 保留等机制防止多个节点同时访问共享存储

3. 心跳与超时设计
	- 合理设置心跳间隔和超时阈值
	- 使用多路径心跳检测（如同时使用网络和串口心跳）

4. 共识算法应用
	- 使用 Raft、Paxos 等共识算法明确领导者身份
	- Raft 通过任期和选举限制防止多领导者出现

5. 人工干预接口
	- 提供手动强制关闭某部分的接口
	- 设计明确的恢复流程处理裂脑后的数据合并
