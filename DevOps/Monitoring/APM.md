APM（Application Performance Monitoring，应用性能监控）是一种软件技术，用于监控、管理和优化软件应用程序的性能、可用性及用户体验。它帮助开发、运维和业务团队实时了解应用在真实环境中的运行状况，快速定位并解决性能问题，确保应用高效、稳定运行。

## 核心目标

1. **确保用户体验**：减少页面加载时间、避免卡顿或崩溃。
2. **保障业务连续性**：快速发现并修复故障，减少停机时间。
3. **优化资源利用**：找出性能瓶颈，提升系统效率，降低成本。
4. **辅助决策**：通过性能数据指导容量规划、架构优化和业务决策。

## 监控维度

1. **端用户体验**
    - **加载时间**：页面、事务或 API 调用的完成时间。
    - **响应时间**：应用对用户操作的反馈速度。
    - **错误率**：应用崩溃、白屏或 API 失败的比例。
    - **用户行为分析**：用户在应用内的点击流、交互路径。
2. **应用架构性能**
    - **事务追踪**：追踪一个用户请求（如“点击支付”）在复杂分布式系统中流经的所有服务（前端、API 网关、微服务A、数据库、缓存等），并记录每个环节的耗时和状态，这是现代 APM 的核心。
    - **代码级性能分析**：定位到具体哪行代码、哪个方法或数据库查询最耗时。
    - **依赖服务性能**：监控数据库、缓存（如 Redis）、消息队列、第三方 API 等外部调用的性能和健康状态。
3. **基础设施与资源**
    - **服务器/容器指标**：CPU、内存、磁盘 I/O、网络流量使用率。
    - **运行时状态**：如 JVM 内存垃圾回收（GC）、.NET CLR 性能计数器等。


## 工作流程

1. **数据采集**
    - **Agent（探针/代理）**：在应用服务器、客户端或容器中植入轻量级探针，自动采集性能数据。这是最常见的方式。
    - **代码埋点（手动/自动）**：在关键业务代码处手动插入监控代码，或依靠框架/APM工具自动注入。
    - **网络嗅探**：通过分析网络流量来推断性能数据（侵入性较低）。
2. **数据处理与存储**
    - 采集的原始数据（指标、追踪、日志）被发送到 APM 服务器。
    - 服务器对数据进行聚合、分析和索引，存储在高性能的时序数据库或分布式存储中。
3. **数据可视化与分析**
    - **仪表盘**：实时展示关键性能指标（KPI）和趋势图。
    - **拓扑图**：自动生成应用架构的依赖关系图，直观显示服务间调用和瓶颈点。
    - **错误分析**：聚合和展示错误堆栈信息，帮助快速排错。
    - **警报**：当指标超过阈值（如错误率飙升、响应时间变慢）时，自动通过邮件、短信、Slack等渠道告警。

## 常见工具

1. **商业产品**：**Datadog**, **New Relic**, **Dynatrace**, **AppDynamics** 等，功能全面，服务成熟。
2. **开源方案**：SkyWalking，Pinpoint，[Jaeger](Jaeger.md)（侧重分布式追踪），通常需要自行部署和维护。
3. **云厂商方案**：**AWS X-Ray**, **Google Cloud Trace**, **Azure Application Insights**，与各自云平台深度集成。
