生成 C++ 程序意味着要从一个或多个文件编译源代码，然后将这些文件链接到可执行文
件（ `*.exe` ）、动态加载库（ `*.dll` ）或静态库（ `*.lib` ）中。

Visual Studio 项目是使用 MSBuild 生成系统构建在一起的代码文件和资产（例如图标、
图像等）的集合。

> [!info] MSBuild
> Microsoft 生成引擎（Microsoft Build Engine，MSBuild），是用于构建应用程序的平台。此引擎为项目文件提供了一个 XML 架构，用于控制生成平台处理和生成软件的方式。 Visual Studio 会使用 MSBuild，但 MSBuild 不依赖于 Visual Studio。
> Visual Studio 中的项目文件（`*.csproj`、`*.vcxproj` 等）包含 MSBuild XML 代码，当你使用 IDE 来生成项目时，此代码就会运行，也可以在在命令行中运行 MSBuild。

## 目标平台

![](_imgs/Pasted%20image%2020230907141600.png)
Visual Studio中经常出现的Debug、Release模式是什么意思？
- Debug 调试版本，它包含调试信息，并且不作任何优化，便于程序员调试程序。
- Release 发布版本，它往往是进行了各种优化，使得程序在代码大小和运行速度上都是最优的，以便用户很好地使用。
其中，Debug 和 Release 并没有本质的界限，它们的不同之处在于一组编译选项，如预定义的宏不同、优化开关的开启与关闭等：
![](_imgs/Pasted%20image%2020230907143547.png)


在目标平台选项中，会出现Any GPU、x86和x64等，这是什么意思呢？
- Any CPU平台下：生成的程序是兼容的，也就是说编译生成的软件在32位操作系统下会以32位的软件模式运行，而在64位操作系统下则会以64位的软件模式运行。
- x86平台下：强制生成的软件为32位软件，不管操作系统是32位还是64位都是以32位模式运行。
- x64平台下：与x86类似，强制生成为64位软件，只能在64位模式运行。


## 相关文件

### 项目管理

`*.sln` 是开发环境中使用的解决方案文件，将一个或多个项目的所有元素组织到单个的解决方案中。此文件存储在父项目目录中.解决方案文件，是一个或多个 `.proj` 的集合。

`.editorconfig` 即 EditorConfig 文件，用于设置在代码库中维持一致的编码风格，例如缩进样式、制表符宽度、行尾字符以及编码等，而无需考虑使用的编辑器或 IDE。 例如，使用 C# 编码时，如果基本代码约定为始终缩进五个空格字符、文档使用 UTF-8 编码，且每一行始终以 CR/LF 结束。

### C&C++ 相关

**`*.vcxproj`** 是C&C++项目文件，可以通过使用任何文本或 XML 编辑器来检查  `*.vcxproj` 文件的内容。[.vcxproj 和 .props 文件结构 | Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/build/reference/vcxproj-file-structure?view=msvc-170)


**`*.vcxproj.filters`** 是位于根项目文件夹中的 MSBuild 格式的 XML 文件，指定哪些文件类型进入解决方案资源管理器中的逻辑文件夹。[vcxproj.filters 文件 | Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/build/reference/vcxproj-filters-files?view=msvc-170)



**`*.vcxproj.user`** 是本地化用户配置，允许多个用户使用自己喜好的方式配置这个项目。

**`*.rc`** 在win32编程中，为方便项目中的资源统一管理，提供了一个格式统一的资源文件，对各种资源进行管理。在程序编译时它会被资源编译器编译生成一个 `*.res` 的二进制文件。

### .NET 相关

`bin/` 目录用来保存项目生成后程序集，有Debug和Release两个版本，分别对应为 `bin/Debug` 和 `bin/Release` 。这个文件夹是默认的输出路径，可以通过**项目属性—>配置属性—>输出路径**来修改。

`obj/` 目录是用来保存每个模块的编译结果，在.NET中，**编译是分模块进行的**，编译整个完成后会合并为一个 `.dll` 或 `.exe` 保存到 `bin` 目录下。因为每次编译时默认都是**采用增量编译**，即只重新编译改变了的模块，`obj` 保存每个模块的编译结果，用来加快编译速度。是否采用增量编译，可以通过**项目属性—>配置属性—>高级—>增量编译**来设置。

`Properties/` 目录定义程序集的属性，项目属性文件夹一般只有一个 `AssemblyInfo.cs` 文件，用于保存程序集的信息，如名称，版本等。这些信息一般与项目属性面板中的数据对应，不需要手动编写。

`*.cs` 类文件，源代码都写在这里，主要就看这里的代码。

`*.resx` 资源文件，一些资源存放在这里，一般不需要看。

`*.csproj` 是C#项目文件，用Visual Studio打开这个文件就可以直接打开这个项目，自动生成。

`*.csproj.user` 是一个配置文件，自动生成的，会记录项目生成路径、项目启动程序等信息。

`*.Designer.cs` 设计文件，自动生成。

`*.aspx` 是网页文件，HTML代码写在这里面。







## 依赖配置

C++ 项目需要调用二进制文件中的函数或访问其中的数据，例如静态库（ `*.lib` ）、动态链接库（ `*.dll` ）、Windows 运行时组件、COM 组件或 .NET 程序集。 在这些情况下，必须配置项目，使它可以在生成时找到该二进制文件。

### 配置静态库（`*.lib`）

1. 如果静态库不是解决方案的一部分：
	1. 右键单击“解决方案资源管理器”中的应用程序项目节点，然后选择“属性” 。
	2. 在“VC++ 目录”属性页中，将包含 LIB 文件的目录的路径添加到“库路径” 。 然后，将库标头文件的路径添加到“包含目录”。![](_imgs/Pasted%20image%2020230907153453.png)
	3. 在“链接器”>“输入”属性页中，将 LIB 文件的名称添加到“附加依赖项”。![](_imgs/Pasted%20image%2020230907153523.png)

2. 如果在同一个解决方案中生成静态库项目：
	1. `#include` 使用引号的静态库的头文件。 在典型解决方案中，路径将以 `../<library project name>` 开头。
	2. 添加对静态库项目的引用。 在“解决方案资源管理器”中的应用程序项目节点下右键单击“引用”，然后选择“添加引用” 。


### 配置动态链接库（`*.dll`）

1. 如果 `*.dll` 不是应用程序解决方案的一部分，则需要 `*.dll` 文件、包含导出函数和类的原型的头文件以及提供所需链接信息的 `*.lib` 文件。
	1.  将 DLL 复制到项目的输出文件夹（也就是那个Debug或者Release文件夹），
	2. 按照适用于静态库的步骤 1-3 来提供头文件和 LIB 文件的路径。

2. 如果 `*.dll`  作为与应用程序相同的解决方案的一部分生成，请执行与静态库相同的步骤。

## 远程调试

为了将开发好的Web程序部署在Windows服务器中，同时需要调试Web程序，可以利用Visual Studio的远程调试功能。

首先是找到远程调试包：`msvsmon.exe`，找到如下文件夹：
![](_imgs/Pasted%20image%2020230906102744.png)
然后将 `Remote Debugger\` 文件夹整体**拷贝到Windows服务器**中，直接打开x64文件夹下的`msvsmon.exe` 程序，即建立连接（第一次打开会跳出窗口，提示设置端口号，之后就是默认4026端口了）。
![](_imgs/Pasted%20image%2020230906102649.png)

然后将需要调试的应用程序部署到服务器，以一个简单的控制台程序为例。首先编译以生成解决方案，然后找到项目所在位置，找到 `bin\Debug\` 文件夹（实际发布可以是Release的，但是为了调试最好还是Debug的），将此文件夹**拷贝到Windows服务器**中。
![](_imgs/Pasted%20image%2020230906103719.png)

双击打开exe，要在程序运行期间，在本地附加远程程序，然后在本地打断点，程序会跳转到断点处。
