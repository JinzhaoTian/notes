JWT（JSON Web Token）是一种开放标准（RFC 7519），用于在不同系统之间安全地传输信息。它通常用于身份验证和授权场景，特别是在分布式系统中，因为它可以以紧凑且自包含的方式传递信息。

### JWT 的结构

JWT 由三部分组成，用点（`.`）分隔：

1. **Header（头部）**  
   包含令牌的类型（通常是 "JWT"）和使用的签名算法（如 HMAC SHA256 或 RSA），例如：
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

2. **Payload（负载）**  
   包含声明（claims），即关于用户或其他数据的声明。声明分为三类：
	- **Registered Claims**：预定义的声明，如 `iss`（签发者）、`exp`（过期时间）、`sub`（主题）等。
	- **Public Claims**：自定义的公开声明。
	- **Private Claims**：双方约定的私有声明。  
    例如：
```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "admin": true
}
```

3. **Signature（签名）**
   用于验证令牌的完整性和真实性。签名是通过将头部和负载用 base64 编码后，用指定的算法和密钥生成的。例如：
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```


### JWT 的工作流程

1. **用户登录**：用户提供凭据（如用户名和密码），服务器验证后生成 JWT 并返回给客户端。
2. **客户端存储**：客户端（如浏览器或移动应用）将 JWT 存储在本地（如 localStorage 或 cookie）。
3. **请求资源**：客户端在后续请求中携带 JWT（通常放在 HTTP 请求头的 `Authorization` 字段中）。
4. **服务器验证**：服务器验证 JWT 的签名和有效期，如果有效则允许访问资源。

### JWT 的优点

- **无状态**：服务器不需要存储会话信息，适合分布式系统。
- **跨域支持**：可以在不同域之间传递信息。
- **自包含**：所有必要信息都包含在令牌中，减少数据库查询。

### JWT 的缺点

- **令牌大小**：JWT 可能会比传统的会话 ID 大，增加网络开销。
- **无法撤销**：一旦签发，无法在有效期内撤销，除非使用额外的机制（如黑名单）。
- **安全性**：如果密钥泄露或存储不当，可能导致安全问题。

### 适用场景

- 单点登录（SSO）
- API 身份验证
- 微服务之间的安全通信
