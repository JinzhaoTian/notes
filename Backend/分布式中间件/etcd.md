etcd 是一个开源的分布式统一键值存储系统，用于分布式系统或计算机集群的共享配置、服务发现，它是 CoreOS 团队发起并开源的项目，现在是 CNCF 的顶级项目，也是 Kubernetes 等核心基础设施的基石。

![](_imgs/Pasted%20image%2020240808101255.png)

> `"etcd"` 这个名字源自 Linux 目录结构中的命名约定：在 UNIX 中，单个系统的所有系统配置文件都包含在一个名为 `/etc` 的文件夹中，"d" 代表 "分布式"。

etcd 使用 [Raft](../../../Distributed%20System/Raft.md) 协议，可确保集群中所有节点之间的数据存储一致性。**etcd 是 Kubernetes 的核心组件之一**，充当主要键值存储库，用于创建可正常运行且具有容错能力的 Kubernetes 集群。 Kubernetes API 服务器会将每个集群的状态数据都存储在 etcd 中。 Kubernetes 使用 etcd 的"观察" 功能来监控这些数据，并在发生变化时自行重新配置。 "观察" 功能会存储代表集群实际状态和理想状态的值，并且可以在这两种状态不同时作出响应。

## 核心特性

1. **键值存储**
    - 数据以键值对形式存储，类似于 Redis 或 ZooKeeper，但设计目标不同。
    - 支持结构化数据（如 JSON）。
2. **强一致性**
    - 使用 [Raft](../../Distributed%20System/Raft.md) 一致性算法保证所有节点数据的一致性和高可靠性。
    - 所有写入操作只有同步到多数节点后才会确认成功。
3. **高可用性**
    - 支持多节点集群，自动容忍机器故障。
    - 通过选举机制避免单点故障。
4. **Watch 机制**
    - 客户端可以监听键的变化，实时获取更新通知。
    - 常用于服务发现或配置动态更新。
5. **租约（Lease）和过期机制**
    - 可以为键绑定租约，租约到期后自动删除对应的键。
    - 常用于实现分布式锁和健康检查。

## 应用场景

1. **Kubernetes 的后端存储**
    - 存储所有集群状态数据：节点信息、Pod 配置、Secrets 等。
    - Kubernetes 的 API Server 通过 etcd 持久化集群状态。
2. **服务发现**
    - 微服务架构中，服务实例启动时在 etcd 注册，停止时自动删除。
    - 客户端通过查询 etcd 发现服务地址。
3. **分布式系统配置管理**
    - 集中存储配置，支持动态更新（通过 Watch 机制通知服务）。
4. **分布式锁与选举**
    - 利用 etcd 的强一致性和租约机制实现安全的分布式协调。
