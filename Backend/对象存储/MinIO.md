MinIO 的不同之处在于它从一开始就被设计为私有/混合云对象存储的标准。 因为 MinIO 是专门为对象而构建的，所以单层架构可以毫不妥协地实现所有必要的功能。 结果是一个同时具有高性能、可扩展性和轻量级的云原生对象服务器。

MinIO 在二级存储、灾难恢复和归档等传统对象存储用例方面表现出色，并且它在机器学习、分析和云原生应用程序工作负载相关的方面独树一帜。


## 核心特点

1. **S3兼容**
    - 完全兼容 Amazon S3 API（支持 RESTful 接口），现有基于 S3 的应用可无缝迁移到 MinIO。
    - 工具链（如 `awscli`、`s3cmd`）可直接操作 MinIO。

2. **高性能**
    - 采用 [Golang](../../Language/Golang/Golang.md) 编写，轻量高效，支持高并发读写。
    - 在标准硬件上可实现每秒数十 GB 的吞吐量。

3. **分布式架构**
    - 支持纠删码（Erasure Coding），提供数据冗余和恢复能力（类似 RAID），无需额外备份。
    - 可横向扩展至数百个节点，组成单一命名空间的大规模存储集群。

4. **轻量部署**
    - 单二进制文件部署，依赖极少（仅需 CPU、内存和磁盘）。
    - 支持 Docker、Kubernetes（如通过 `k8s` 或 `helm` 部署）。

5. **多云支持**
    - 数据可跨公有云、私有云和边缘节点同步或分层存储。


## 核心概念

- **Bucket（桶）**：类似文件夹，用于存储对象（文件）。
- **Object（对象）**：存储的实际数据（如图片、视频、日志等）及其元数据。
- **Server Pool（服务器池）**：一组节点组成的分布式存储单元。
- **Erasure Code（纠删码）**：将数据分块并编码，允许部分节点故障时仍可恢复数据。


## 常见用途

1. **云原生应用存储**：为 Kubernetes 提供持久化存储（通过 CSI 驱动或直接集成）。
2. **大数据与分析**：存储海量日志、备份文件，支持 Spark、Hive、Presto 等分析工具。
3. **备份与灾备**：替代传统 NAS/SAN，低成本实现冗余存储。
4. **AI/ML 数据湖**：集中管理训练数据集和模型文件。



## 安装使用

### Docker

**单机运行**：
```bash
docker run -p 9000:9000 -p 9001:9001 minio/minio server /data --console-address ":9001"
```

**分布式部署**：
```bash
minio server http://node{1...4}/data
```




## 架构

MinIO 被设计为云原生，可以作为由外部编排服务（如 Kubernetes）管理的轻量级容器运行。 整个服务器是一个大约 40MB 的静态二进制文件，并且在使用 CPU 和内存资源方面非常高效 - 即使在高负载下也是如此。

![](_imgs/Pasted%20image%2020250710111603.png)


![](_imgs/Pasted%20image%2020250710111842.png)


MinIO 将数据和元数据作为对象一起写入，从而消除了对元数据数据库的需求。 此外，MinIO 执行所有功能（擦除代码、位腐烂检查、加密）作为内联、严格一致的操作。 结果是 MinIO 非常有弹性。

每个 MinIO 集群都是分布式 MinIO 服务器的集合，每个节点有一个进程。 MinIO作为单进程运行在用户空间，使用轻量级协程实现高并发。 驱动器被分组为擦除集（默认情况下每组 16 个驱动器），并且使用确定性哈希算法将对象放置在这些集中。

MinIO 专为大规模、多数据中心的云存储服务而设计。 每个租户运行他们自己的 MinIO 集群，与其他租户完全隔离，使他们能够保护他们免受升级、更新和安全事件的任何中断。 每个租户通过跨地域联合集群独立扩展。
