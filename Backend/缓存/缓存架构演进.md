
## 演进

### 阶段一：本地缓存

如果数据库慢，那就在应用层加个缓存，可以使用一个简单的 `ConcurrentHashMap` ：

```java
public class LocalCache {
    private final ConcurrentHashMap<String, Object> cache = new ConcurrentHashMap<>();
    private final int maxSize = 10000;

    public Object get(String key) {
        return cache.get(key)；
    }

    public void put(String key， Object value) {
        // 简单粗暴的LRU淘汰策略
        if (cache.size() >= maxSize) {
            cache.remove(cache.keys().nextElement())；
        }
        cache.put(key， value)；
    }
}
```

QPS 从原来的 5000 直接翻了一倍，但随着业务增长，单机内存开始吃紧，并且一旦应用重启，缓存全部丢失，冷启动时数据库又被瞬间打死。

**本地缓存只能治标，不能治本**。


### 阶段二：[Redis](../../Database/Redis/Redis.md) 

相比本地缓存，Redis 最大的优势就是**数据持久化**和**多实例共享**

```java
@Service
public class DistributedCacheService {
    @Autowired
    private RedisTemplate<String， Object> redisTemplate；

    public Object getFromCache(String key) {
        try {
            return redisTemplate.opsForValue().get(key)；
        } catch (Exception e) {
            // Redis挂了，直接查数据库
            log.warn("Redis异常，降级到数据库查询"， e)；
            return queryFromDB(key)；
        }
    }

    public void setCache(String key， Object value， long expireTime) {
        redisTemplate.opsForValue().set(key， value， expireTime， TimeUnit.SECONDS)；
    }
}
```

并且可以添加 Redis 集群部署、主从复制、数据持久化，系统稳定性大幅提升。但是随之而来的新问题是**网络延迟**，虽然 Redis 很快，但毕竟要走网络 IO ，平均耗时从本地缓存的 0.1ms 变成了 1~2ms 。对于那些超高频访问的热点数据，这点延迟放大后就不容忽视了。

### 阶段三：多级缓存架构

本地缓存快但容量小，Redis 慢但容量大，那可以结合本地缓存和 Redis ，设计了一套**多级缓存架构**：
```java
@Component  
public class MultiLevelCache {
    private final LoadingCache<String， Object> localCache;
    private final RedisTemplate<String， Object> redisTemplate;

    public MultiLevelCache() {
        this.localCache = Caffeine.newBuilder()
            .maximumSize(5000)  // 本地缓存只存热点数据  
            .expireAfterWrite(5, TimeUnit.MINUTES)  
            .build(this::loadFromRedis);
    }

    public Object get(String key) {  
        try {  
            // L1缓存：本地缓存命中，直接返回  
            return localCache.get(key);
        } catch (Exception e) {
            log.error("多级缓存查询失败"， e);
            return queryFromDB(key);
        }
    }
 
    private Object loadFromRedis(String key) {
        // L2缓存：Redis缓存命中
        Object value = redisTemplate.opsForValue().get(key);
        if (value != null) {
            return value;
        }

        // L3兜底：查询数据库并回写缓存  
        value = queryFromDB(key);
        if (value != null) {  
            redisTemplate.opsForValue().set(key, value, 30, TimeUnit.MINUTES);  
        }
        return value;
    }  
}
```

**分层存储**：
- **L1层（本地缓存）**：存储最热点的数据，命中率虽然只有 20% ，但这 20% 的请求响应时间缩短到 0.1ms
- **L2层（Redis）**：存储次热点数据，命中率能达到 70% ，网络延迟 1-2ms 可以接受
- **L3层（数据库）**：兜底方案，剩下 10% 的请求直接查库



## 缓存一致性

### 方法一：异步刷新 + 兜底机制

```java
@EventListener
public void handleDataUpdate(DataUpdateEvent event) {
    String key = event.getKey();

    // 1. 立即删除本地缓存
    localCache.invalidate(key);

    // 2. 异步删除Redis缓存，避免阻塞主流程
    CompletableFuture.runAsync(() -> {
        redisTemplate.delete(key);
    });

    // 3. 设置较短的过期时间作为兜底
    // 即使缓存删除失败，数据也会在5分钟后自动过期
```
