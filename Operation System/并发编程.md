并发编程（Concurrent Programming）是一种**编程范式**，旨在让程序能够**同时处理多个任务**，从而提高效率、响应速度或资源利用率。它通过合理地组织和管理多个执行流（如线程、进程、协程等），使它们在宏观上看似“同时”运行（即使单核 CPU 通过时间片轮转实现并发）。

## 并发 vs 并行

- **并发（Concurrency）**： 多个任务**交替执行**（单核 CPU 通过快速切换模拟“同时”运行）
    - 例如：一个线程处理网络请求，另一个线程更新 UI 
- **并行（Parallelism）**： 多个任务**真正同时执行**（需要多核 CPU 或分布式系统）
    - 例如：多线程分别计算矩阵的不同部分

>  **并发是问题分解的方式，并行是执行的方式。**


## 为什么需要并发编程？

- **提高吞吐量**：服务器同时处理多个客户端请求。
- **降低延迟**：UI 线程保持响应，后台线程执行耗时任务。
- **充分利用多核CPU**：并行计算加速程序运行。
- **简化复杂问题**：将任务拆解为独立的并发单元（如生产者-消费者模型）。


## 核心问题

- [调度](调度.md)（Scheduling）：决定哪个任务在何时由哪个执行单元运行的过程
- [配合](配合.md)（Coordination）：多个并发执行单元之间的同步和通信机制，确保它们按照预期的方式交互



## 实现方式
### 多进程（Multiprocessing）

- **特点**：进程间资源隔离，稳定性高，但开销大
- **适用场景**：需要强隔离的任务（如 Chrome 浏览器每个标签页一个进程）
- **示例（Python）**：
  ```python
  from multiprocessing import Process

  def task(name):
      print(f"Process {name} running")

  if __name__ == "__main__":
      p1 = Process(target=task, args=("A",))
      p2 = Process(target=task, args=("B",))
      p1.start()
      p2.start()
  ```

### 多线程（Multithreading）

- **特点**：线程共享进程资源，轻量但需处理同步问题
- **适用场景**：I/O 密集型任务（如 Web 服务器）
- **示例（Java）**：
  ```java
  public class Main {
      public static void main(String[] args) {
          Thread t1 = new Thread(() -> System.out.println("Thread 1"));
          Thread t2 = new Thread(() -> System.out.println("Thread 2"));
          t1.start();
          t2.start();
      }
  }
  ```

### 协程（Coroutine）

- **特点**：用户态轻量级线程，由程序自身调度，开销极小
- **适用场景**：高并发 I/O（如 Python 的 `asyncio` 、Go 的 `goroutine` ）
- **示例（Python asyncio）**：
  ```python
  import asyncio

  async def fetch_data():
      print("Start fetching")
      await asyncio.sleep(2)  # 模拟I/O操作
      print("Data fetched")

  asyncio.run(fetch_data())
  ```

### 异步编程（Async/Await）

- **特点**：基于事件循环的非阻塞模型，避免线程切换开销
- **适用场景**：高并发网络请求（如 Node.js ）
- **示例（JavaScript）**：
  ```javascript
  async function getData() {
      const response = await fetch("https://api.example.com");
      console.log(await response.json());
  }
  getData();
  ```


## 核心挑战

### 竞态条件（Race Condition）

- **问题**：多个线程同时修改共享数据，导致结果不可预测。
- **解决**：使用锁（`Mutex`）、原子操作（`Atomic`）或不可变数据。

### 死锁（Deadlock）

- **问题**：多个线程互相等待对方释放资源，导致程序卡死。
  - 例如：线程A持有锁1请求锁2，线程B持有锁2请求锁1。
- **解决**：按固定顺序获取锁，或使用超时机制。

### 资源饥饿（Starvation）

- **问题**：某些线程长期得不到资源。
- **解决**：公平调度（如`FairLock`）。

### 上下文切换开销

- **问题**：频繁切换线程/进程会消耗CPU资源。
- **解决**：减少线程数量（如使用线程池）、改用协程。


## 常用并发模型

| **模型**      | **描述**                | **示例语言/框架**           |
| ----------- | --------------------- | --------------------- |
| **共享内存**    | 线程直接读写共享变量            | Java `synchronized`   |
| **消息传递**    | 通过通信（如消息队列）共享数据       | Go的 `channel` ，Erlang |
| **Actor模型** | 每个 Actor 独立处理消息，无共享状态 | Akka（Scala/Java）      |
| **数据并行**    | 将数据分片并行处理             | OpenMP（C++），CUDA      |

## 应用场景

- **Web服务器**：Nginx通过多进程/多线程处理并发请求。
- **数据库系统**：MySQL使用线程池管理连接。
- **实时系统**：股票交易系统并行处理大量订单。
- **科学计算**：多线程加速矩阵运算（如NumPy）。
