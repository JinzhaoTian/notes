运行时（Runtime）是一个广义的概念，指的是程序在目标机器上运行所需的辅助支撑系统，它提供了程序运行所需的核心库、服务和管理功能（如内存管理、垃圾回收、异常处理等）。

> [!tip] 比喻：开餐厅
> 想象一下，你要开一家餐厅（**编写一个程序**）：
> 1. **自己编写核心菜谱（你的业务逻辑）**：
> 	- 你精心研制了招牌菜的独家配方（这相当于你写的 `main` 函数和你自己写的独特算法）。
> 	- 你把这份独家配方写了下来（这相当于**编译**你的代码）。
> 2. **使用公共基础设施（调用 C 标准库）**：
> 	- 你的餐厅需要水电、燃气、网络（这相当于调用 `printf`, `malloc`, `fopen` 等函数）。
> 	- 你**不会自己去发电、挖水井、建燃气管道**。你直接付费给电力公司、自来水公司（这相当于**链接**到 glibc）。
> 3. **开业运营（程序运行）**：
> 	- 顾客来点你的招牌菜（**运行你的程序**）。
> 	- 你开始按照菜谱做菜（**CPU 执行你编译好的代码**）。
> 	- 在做菜过程中，你需要用电来开炉灶、用水来洗菜（**你的程序调用 `printf` 等函数**）。
> 	- 此时，电力公司和水务公司就开始工作了，为你提供必需的服务（**glibc 运行时库中的 `printf` 实现代码开始执行**）。
> 
> **关键点**：你的餐厅（程序）的核心价值是那道招牌菜（你的业务逻辑），而不是自己去造发电厂。同样，你的程序的核心是你写的算法，而不是自己去实现如何与屏幕驱动交互来打印一个字符这种复杂且通用的底层操作。

> [!success] 简单理解
> 我们写代码的时候**本身就是调库**，虽然我们的代码被编译成机器可直接执行的二进制码（机器码），但是**库本身也是需要被执行的**，这部分库的代码就被抽出来共用（运行时），我们的程序编译的时候**在链接阶段就将所调用的库代码链接进来**，形成一个完整的可执行文件，执行的时候就可以执行到库代码。
> 
> **我们程序编译出的代码 + 运行时的库代码加起来 = 一个完整的程序**。

## 运行原理

从技术上讲，这个过程分为两步：

1. **编译（Compile）**：
    - 编译器（如 `gcc`）将你的 `.c` 源文件翻译成**目标文件（`.o` 文件）**，这个目标文件里已经是二进制机器码了。
    - 当你调用 `printf("Hello")` 时，编译器会在这个目标文件中留下一个标记或存根（stub），相当于写着：“注意！这里需要调用一个名为 `printf` 的函数，但这个函数的具体实现我现在没有，稍后请补上。”
2. **链接（Linking）**：
    - 链接器（`ld`，通常由 `gcc` 调用）登场了，它的任务就是把你的目标文件和所有需要的库（最重要的是 glibc）“粘”在一起，形成一个完整的可执行文件。
    - 链接器有两种工作方式：
        - **静态链接（Static Linking）**：将库中的代码（如 `printf` 的完整实现）直接复制到最终的可执行程序中。这样生成的文件非常大，但好处是它可以独立运行，不依赖外部库。
        - **动态链接（Dynamic Linking）**：**这是默认且最常见的方式**。链接器**不会**将库代码复制到你的程序中，它只是在你的程序里记录一条信息：“我这个程序运行需要 `libc.so.6` 这个库文件。” 最终生成的文件很小。


## 主要形式 

1. **系统内置运行时**：操作系统自带的为系统组件和基础应用提供支持（如 Windows 的 `MSVCRT`，Linux 的 `glibc`）的运行时。
2. **独立安装的运行时**：需要用户手动安装，为特定平台开发的应用程序提供支持（如 `.NET Framework`, `Java JRE`, `Visual C++ Redistributable`）。
3. **应用自带运行时**：开发者将运行时和应用程序一起打包分发，避免用户单独安装和环境问题（如很多 Electron 应用、打包的 Python 应用）。

## 常见运行时

### Windows

1. **Visual C++ Redistributable Runtime（VCRedist）**
	- 用 Visual C++ 编写的程序所依赖的运行时库（如 `MSVCP140.dll`，`VCRUNTIME140.dll`），不同版本的 Visual Studio 对应不同版本的运行时，但它们现在共享相同的重分发文件（如 `VC_redist.x64.exe`）。
	- 常见于几乎所有的大型游戏和许多专业软件（如 Adobe 系列、AutoCAD）都依赖它，这是 Windows 上最常见的**需要手动安装**的运行时之一。

2. **.NET Framework / .NET (Core) Runtime**
	- 微软主要的应用程序开发平台，`.NET Framework`（4.8 是最终版）是旧时代的产物，深度集成于 Windows，`.NET`（5, 6, 7, 8...）是它的现代化、跨平台、高性能的开源继任者。
	- 主要包含基类库（BCL）、公共语言运行时（CLR）或 CoreCLR（用于 `.NET Core`）、即时编译（JIT）等。
	- 常见于大量的桌面程序（WinForms，WPF）、后端服务、游戏修改工具（Mod）。

3. **Universal C Runtime（UCRT）**
	- Windows 10 及之后版本的系统组件，提供了 C 标准库（如 `stdio.h`, `stdlib.h`）的实现，对于旧系统（如 Win7/8.1），它可能作为更新的一部分分发。
	- 常见于新的 C/C++ 程序，尤其是用现代 Visual Studio 编译的。

4. **DirectX End-User Runtime**
	- 包含用于多媒体、尤其是游戏和视频的 API 库（如 Direct3D），**现代 Windows 系统已内置**，但游戏安装包常会附带所需版本的特定文件（如 `d3dx9_43.dll`）。


### Linux

1. **glibc（GNU C Library）**：
	- Linux 系统**最核心的运行时库**，实现了 C 标准库和系统调用接口，**几乎所有动态链接的程序**都依赖于它，是 Linux 系统的基石。

2. **核心工具链运行时**：
	- 如 `gcc`, `libstdc++`（GNU 的 C++ 标准库实现），`libgcc` 等，这些是编译和运行 C/C++ 程序的基础。

### macOS

1. **系统库**：
	- 如 `libSystem.B.dylib`（它本身包含如 `libc`, `libm` 等）是所有程序的基础。

2. **dyld（动态链接器）**：
	- `dyld` 是 macOS 的动态链接器，相当于 Linux 的 `ld.so`。

3. **Objective-C 和 Swift Runtime**
	- macOS 和 iOS 生态系统的核心，系统内置了运行 Objective-C 和 Swift 语言所需的全部运行时库（如内存管理、方法分发机制）。这就是为什么 macOS 可以原生运行这两种语言开发的程序。


### 通用运行时

1. **Java Virtual Machine（JVM）**：
	- 如 `OpenJDK`，运行 Java 应用程序的标准环境。
2. **.NET Runtime**：
	- 如 `.NET 8.0`，运行跨平台的 .NET 应用。
3. **Python**：
	- 如 `python.exe` 解释器，运行 Python 脚本。
4. **Node.js**：
	- 运行 JavaScript 服务器端代码或基于 Electron 的桌面应用。
5. **Golang Runtime**：
	- 是 go 语言运行所需要的基础设施，提供协程调度、内存分配、GC等功能支持。



## 编程语言运行时

1. [C/C++ Runtime](../Language/C++/原理/C++%20运行时.md)：
	- **运行原理**：编译器直接翻译成机器码（Binary），主要由 C++ 标准库（STL）和 C 运行时库（CRT）组成。
	- **内存管理**：程序员手动管理内存（`new`/`delete`）或利用 RAII（资源获取即初始化）机制通过析构函数自动释放，没有自动垃圾回收（GC）。
	- **线程模型**：直接映射到操作系统的原生线程。
	- **特点**：启动速度最快，运行效率最高，但开发者需要承担处理内存泄漏和越界的责任。

2. [Golang Runtime](../Language/Golang/原理/Golang%20运行时.md)：
	- **运行原理**：编译器将 Go 代码编译成二进制文件，同时会将一个几 MB 大小的运行时源码直接链接到程序中。
	- **内存管理**：采用分代式并发垃圾回收（三色标记清除算法），旨在保持极低的停顿时间。
	- **并发模型**：（用户态）Goroutine M:N 协程调度，在少量系统线程上切换成千上万个轻量级协程（有栈协程）。
	- **特点**：部署简单（单个二进制文件），并发性能极强，在开发效率和运行性能之间取得了极佳平衡。

3. [.NET Runtime](../Language/CS/原理/dotnet%20Runtime.md)：
	- **运行原理**：在编译时源码被编译成中间语言（MSIL/CIL），在运行期时 .NET CLR （Common Language Runtime）中的 JIT（即时编译器）将中间语言根据当前硬件环境翻译成机器码。
	- **内存管理**：使用分代垃圾回收机制（Generational GC），将内存对象分为 0、1、2 代，提高回收效率。
	- **并发模型**：异步 `async` / `await`（无栈协程），线程池 `Task`
	- **特点**：跨平台能力强（.NET Core），具有极强的类型安全和反射（Reflection）能力。

4. JavaScript / TypeScript：JavaScript 的运行时环境（如 Chrome 的 [V8 引擎](../Language/Node/运行原理/V8%20引擎.md)、[Node.js](../Language/Node/Node.md)、[Bun](../Language/JavaScript/Bun.md) 等）非常复杂，旨在让动态语言跑出接近静态语言的速度。在运行阶段，TypeScript 已被擦除并转为 JavaScript，因此它的运行时特性与 JavaScript 完全一致。
	- **运行原理**：
		- **混合执行**：V8 先解释执行字节码，然后通过 JIT（Just-In-Time）编译，将经常运行的“热点代码”优化为机器码。
		- **事件循环（Event Loop）**：这是 JS 运行时的灵魂。它是单线程的，通过任务队列处理所有异步操作（I/O、定时器）。
	- **内存管理**：自动 GC，主要使用 Scavenge (新生代) 和 Mark-Sweep (老生代) 算法。
	- **并发模型**：单线程 + 事件循环

5. [Python](../Language/Python/原理/Python%20Runtime.md)：
	- **运行原理**：（以 CPython 为例）Python 源码编译成字节码（`.pyc`），然后由 Python 虚拟机（PVM）逐条解释执行。
	- **内存管理**：
	    - **引用计数**：主要手段，引用归零立即释放。
	    - **循环垃圾回收**：辅助手段，解决循环引用问题。
	- **关键约束**：全局解释器锁（Global Interpreter Lock，GIL）保证同一时刻只有一个线程在执行字节码，这限制了 Python 在多核 CPU 上的并发计算能力。
	- **特点**：动态性极强，开发速度快，但计算密集型任务性能较弱。
