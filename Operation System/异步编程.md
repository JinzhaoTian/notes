异步编程是一种**编程范式**，允许程序在等待某些操作（如 I/O 、网络请求等）完成时继续执行其他任务，而不是阻塞等待。

异步**本身不是内核机制**，但它**依赖于操作系统提供的内核机制**来实现高效的[非阻塞 IO](../Computer%20Network/非阻塞%20IO.md) 操作。

## 核心概念

1. **非阻塞执行**：程序不会因为等待某个操作完成而停止运行
2. **事件驱动**：操作完成后通过回调、事件或通知机制处理结果
3. **并发处理**：可以同时处理多个任务，提高资源利用率

## 核心机制

1. **回调函数(Callbacks)**：最基本的异步处理方式，操作完成后调用指定函数
2. **Promises/Futures**：表示异步操作最终完成或失败的对象
3. **async/await**：语法糖，使异步代码看起来像同步代码
4. **事件循环(Event Loop)**：管理和调度异步任务的核心机制

### 事件循环

![](imgs/Pasted%20image%2020250623164453.png)


**事件循环**（**Event Loop**）是异步编程的核心机制，用于高效管理和调度任务（如 I/O 操作、定时器、用户交互等），避免程序阻塞。

#### 核心逻辑

1. **检查是否有待处理的事件**（如文件读取完成、定时器到期、网络请求返回等）
2. **执行对应的回调函数**
3. **重复这一过程**，直到没有任务需要处理

#### 实现

1. **浏览器环境中的事件循环**
	- 所有现代浏览器都实现了[标准的事件循环机制](../../Language/Node/Node%20基础架构.md#浏览器事件循环)
2. [libuv 中的事件循环](../../Computer%20Network/IO库/libuv.md#事件循环)
	- Node.js 基于 libuv 实现了更复杂的事件循环
3. libevent：轻量级的事件通知库
4. Boost.Asio：C++ 的异步 I/O 库，提供类似事件循环的功能
5. Python asyncio：Python 的异步 I/O 框架，有自己的事件循环实现
6. Java NIO：Java 的非阻塞 I/O 框架，Selector 提供类似功能
7. **操作系统级实现**：
	- [epoll](../../Computer%20Network/IO%20多路复用.md#epoll)（Linux）
	- [kqueue](../../Computer%20Network/IO%20多路复用.md#kqueue)（BSD/macOS）
	- [IOCP](../../Computer%20Network/IO%20多路复用.md#IOCP)（Windows）


### 回调函数

回调函数（Callback Function）是异步编程中最基础、最核心的机制之一，它通过**将函数作为参数传递给其他函数**，在特定事件发生或异步操作完成时被调用。


## 对比

| 特性       | 异步编程    | 多线程编程      | 多进程编程           |
| -------- | ------- | ---------- | --------------- |
| **执行单元** | 任务/协程   | 线程         | 进程              |
| **并发模型** | 单线程事件循环 | 共享内存并行     | 独立内存并行          |
| **切换成本** | 极低(纳秒级) | 中(微秒级)     | 高(毫秒级)          |
| **内存占用** | 低(共享内存) | 中(共享堆，独立栈) | 高(完全独立)         |
| **数据共享** | 直接访问    | 需要同步机制     | IPC 机制(管道/消息队列) |
| **适用场景** | I/O 密集型 | I/O 和计算混合型 | 计算密集型           |

### 关键区别

1. **执行模型**
	- **异步**：单线程内任务切换，遇到 I/O 时挂起当前任务执行其他任务
	- **多线程**：多个线程并行执行，由操作系统调度
	- **多进程**：多个进程完全独立执行，有各自的内存空间

2. **资源消耗**
	- **异步**：内存占用最少，只需维护任务状态
	- **多线程**：每个线程需要独立栈空间（通常几 MB ）
	- **多进程**：内存消耗最大，完全复制进程空间

3. **适用场景**

| 场景类型      | 异步编程  | 多线程   | 多进程   |
| --------- | ----- | ----- | ----- |
| 高并发Web服务器 | ★★★★★ | ★★★☆  | ★★☆   |
| 科学计算      | ★☆☆   | ★★★☆  | ★★★★★ |
| 数据库访问     | ★★★★★ | ★★★★☆ | ★★☆   |
| GUI应用程序   | ★★★★★ | ★★★★☆ | ★☆☆   |
| 爬虫程序      | ★★★★★ | ★★★☆  | ★★★☆  |

## 组合

1. 异步 + 多线程
	- **适用场景**：I/O 密集型为主，少量 CPU 密集型任务
	- **优势**：避免阻塞事件循环
2. 异步 + 多进程 
	- **适用场景**：需要真正的并行计算
	- **优势**：利用多核



## 与协程的关系

异步编程和[协程](协程.md)是现代并发编程中紧密相关的两个概念，它们相互配合但各有侧重。

1. 协程是异步编程的实现手段，为异步编程提供了**最佳的执行单元**
	- **轻量级**：一个协程通常只需几 KB 内存（线程需要 MB 级）
	- **低成本切换**：协程切换在用户态完成（无需内核介入）
	- **可控性**：由程序员或运行时显式控制切换时机

2. 异步编程是协程的**主要应用场景**，赋予协程实际价值，没有异步编程需求，协程只是理论概念：
	- **I/O等待问题**：传统同步编程在 I/O 时阻塞线程
	- **资源浪费**：线程在等待时无法执行其他任务
	- **解决方案**：协程 + 异步 I/O = 高效并发

3. 异步编程和协程是完美组合，二者结合形成了**用户态并发**的黄金标准
    - **资源高效**：单线程可处理数万协程
    - **逻辑清晰**：用同步写法实现异步效果
    - **性能卓越**：避免线程切换开销
    - **开发友好**：错误堆栈完整可追踪

4. 现代语言普遍采用这种组合
	- Python asyncio
	- JavaScript async
	- Go goroutine


## 不是纯内核机制

- **可移植实现**：同一套 `async` / `await` 代码可在不同内核机制的 OS 上运行
- **语言层抽象**：开发者不直接接触 `epoll` 等系统调用
- **多范式组合**：可与线程池、进程池等组合使用
- **无特权要求**：用户程序无需特殊权限即可使用异步编程
