ABI（Application Binary Interface，应用程序二进制接口）是一套约定俗成的**规则和标准**，它定义了**已编译的二进制程序**如何与操作系统、库或其他已编译的程序进行交互。

## 主要内容

ABI 是一个涵盖多方面内容的规范，主要包括：

1. **函数调用约定**
    - 函数参数如何传递？（是通过CPU寄存器还是堆栈？顺序是从左到右还是从右到左？）
    - 函数的返回值放在哪里？
    - 调用函数时，谁负责清理堆栈？（是调用者还是被调用者？）
2. **系统调用约定**
    - 应用程序如何向操作系统内核发起请求？例如，在 x86-64 Linux 上，通常使用 `syscall` 指令，并将系统调用号放在 `rax` 寄存器中。
3. **数据类型的大小、对齐和对齐方式**
    - `int` 类型是 4 个字节吗？`long` 是 4 字节还是 8 字节？
    - 一个结构体 `struct` 在内存中是如何布局的？成员之间是否有为了性能而插入的“填充”字节？
4. **名称修饰**
    - 编译器如何将函数名、变量名等符号转换成链接器可以识别的唯一名称。这对于支持函数重载的 C++ 尤其重要。不同编译器（如 GCC 和 MSVC）的修饰规则不同，导致它们的二进制文件通常无法直接互操作。
5. **异常处理**
    - 当程序抛出异常时，如何展开调用堆栈并找到正确的 `catch` 块？
6. **目标文件格式**
    - 编译后的二进制文件（如 `.o` 和 `.so` / `.dll` 文件）遵循什么格式？例如，Linux 普遍使用 ELF，而 Windows 使用 PE。


## 重要性

1. **互操作性：** 它允许用不同编程语言（如 C、C++、Rust）编写的模块，只要遵循相同的 ABI，就可以相互调用。
2. **链接：** 确保你的程序能够正确地与系统库（如 `libc.so`）链接在一起。
3. **运行时稳定性：** 操作系统和库的开发者如果希望发布一个新版本而**不强制所有用户重新编译他们的软件**，就必须保持 ABI 的向后兼容性。这被称为 **ABI 稳定性**。


## 常见 ABI

1. **System V ABI**： 这是类 Unix 系统（包括 Linux 和 macOS）在 x86-64 架构上的标准 ABI。
2. **Microsoft x64 ABI**： 这是 Windows 在 x86-64 架构上使用的 ABI。
