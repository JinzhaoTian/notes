Redis Stream 是 Redis 5.0 引入的一种新的数据结构，它本质上是一个只追加的日志（append-only log），专门为实现高效、可靠的消息队列和流处理系统而设计。

> [!tip]- 产生的背景
> 
> 在 Stream 出现之前，开发人员也用 Redis 的其他数据结构来构建简单的消息队列，比如：
> - **List（列表）**：使用 `LPUSH`/`RPOP` 可以实现一个简单的队列。
>    - **缺点**：没有内置的消息确认机制。一个消息被 `RPOP` 取出后就从 List 中消失了，如果消费者处理失败，消息就丢失了。
> - **Pub/Sub（发布/订阅）**： 可以实现消息的广播。
>    - **缺点**：消息是**即时的、非持久化的**，如果消费者中途下线，重新连接后是无法收到离线期间的消息的。
> 
> **Redis Stream 就是为了解决这些痛点而生的**，它提供了：
> 1. **消息持久化**：所有消息都会被持久保存在内存中。  
> 2. **消息回溯**：消费者可以随时重新读取历史消息。
> 3. **消费者组**：这是最强大的特性，允许一组消费者协同处理同一个 Stream，实现负载均衡和故障转移。

## 核心概念

一个 Stream 由一系列条目（Entry）组成，每个条目包含：
1. **一个唯一的、递增的 ID**：通常是时间戳-序列号的格式（例如 `1633041600000-0`），这个 ID 可以由 Redis 自动生成，也可以由用户指定（但必须大于上一个 ID）。
	- **范围查询**：
		- `XADD mystream * name Alice` （`*` 表示让 Redis 自动生成 ID）
		- `XRANGE mystream 1633041600000-0 1633041602000-0` （查询指定 ID 范围的消息）
		- `XREVRANGE mystream + - COUNT 10` （逆序查询，相当于查看最新的 10 条消息）
	- **消费者组**：消费者组允许你将消息的消费负载分摊到多个消费者上，并确保每条消息只被组内的一个消费者处理。
> [!tip] 工作流程
> 1. 生产者使用 `XADD` 向 Stream 发送消息。
> 2. 消费者组内的消费者使用 `XREADGROUP` 命令从 Stream 读取消息。 
> 3. 当一个消费者读取一条消息后，这条消息就会进入**待处理状态**。
> 4. 消费者处理完消息后，必须发送 `XACK` 命令来确认消息已处理。确认后，消息才会从待处理列表中移除。
> 5. 如果一个消费者崩溃了，它没有确认（ACK）的消息在经过一段时间后，会被重新分配给组内的其他消费者进行处理，从而实现了**故障转移**。

2. **多个键值对（Key-Value Pairs）**：这是消息的实际内容，如 `{“name”: “Alice”, “action”: “login”}`。
```
Redis Stream: "mystream"
-----------------------------------------------------------------------------
ID: 1633041600000-0    { "user": "Alice", "action": "login" }
ID: 1633041601000-0    { "user": "Bob", "action": "purchase", "item": "book" }
ID: 1633041602000-0    { "user": "Charlie", "action": "logout" }
... (新的消息只能追加到尾部) ...
```


## 使用场景

1. **消息队列**：最常见的用途，实现任务队列、事件驱动架构。
2. **实时数据流处理**：收集日志、用户行为数据，然后由多个消费者进行实时分析、统计或存储。
3. **事件溯源**：将所有状态变化的事件作为记录持久化在 Stream 中，可以随时回溯系统状态。
4. **消息广播与持久化**：替代传统的 Pub/Sub，实现即使消费者下线也不会丢失消息的广播机制。


## 与 Kafka 的对比

| 特性        | Redis Stream      | Apache Kafka                   |
| --------- | ----------------- | ------------------------------ |
| **定位**    | 轻量级、内存式、嵌入式消息队列/流 | 高性能、分布式、持久化的大数据消息总线            |
| **数据存储**  | 主要存储在内存中（可持久化到磁盘） | 主要存储在磁盘上                       |
| **吞吐量**   | 非常高（因为内存操作）       | 极高（通过磁盘顺序读写和零拷贝技术）             |
| **数据规模**  | 受限于内存大小，适合中小规模    | 支持海量数据（TB/PB 级）                |
| **集群与运维** | 简单，与 Redis 集群集成   | 复杂，需要独立的 ZooKeeper 和 Broker 集群 |
| **功能丰富度** | 核心消息队列功能          | 生态系统更丰富，连接器、流处理等               |
 Redis Stream 是一个内置在 Redis 中的、简单易用但功能强大的轻量级 Kafka，如果你的系统已经使用了 Redis，并且需要一个可靠的消息队列，不希望引入和维护像 Kafka 这样复杂的中间件，那么 Redis Stream 是一个非常完美的选择。
