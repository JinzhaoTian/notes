
[一致性哈希](../../Distributed%20System/Consistent%20Hashing.md) 和 Redis 的哈希槽（Hash Slot）都是用于分布式系统中数据分片的算法，但它们在设计和实现上有显著差异。

1. **共同目标**：两者都用于解决数据在分布式系统中的分片和定位问题
2. **哈希思想**：都基于哈希函数将数据映射到特定节点
3. **负载均衡**：都旨在实现数据在各节点间的均衡分布

Redis 集群必须使用哈希槽，这是其集群架构的核心设计，其他分布式系统（如 Memcached 、 Cassandra 等）通常采用一致性哈希。

| 特性       | 一致性哈希    | Redis哈希槽       |
| -------- | -------- | -------------- |
| **分片方式** | 连续的哈希环   | 固定数量的槽（16384个） |
| **数据迁移** | 仅影响相邻节点  | 槽迁移影响精确范围      |
| **扩展性**  | 动态增减节点   | 需要手动重分配槽       |
| **复杂度**  | 实现相对简单   | 需要维护槽映射表       |
| **使用场景** | 通用分布式系统  | 专为 Redis 集群设计  |
| **重平衡**  | 自动但可能不均  | 手动但更精确控制       |
| **虚拟节点** | 常用（解决热点） | 不使用此概念         |

#### 独特设计

1. **固定槽数**：Redis 集群使用固定的 16384 个槽，而非连续的哈希空间
2. **显式映射**：每个槽明确映射到特定节点，维护槽分配表
3. **精确控制**：管理员可以精确控制哪些槽在哪些节点上
4. **批量迁移**：支持多个槽同时迁移，效率更高
