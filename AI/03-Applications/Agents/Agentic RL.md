Agentic RL（智能体强化学习）是一种新兴的训练范式，旨在将大语言模型（LLM）从被动的“文本生成器”转变为能够在复杂动态环境中自主决策、规划并采取行动的智能体，是一个属于“后训练”（Post-training）阶段的核心技术。

|          | **传统方法 (如 RLHF/DPO)** | **Agentic RL**             |
| -------- | --------------------- | -------------------------- |
| **问题建模** | 单步马尔可夫决策过程 (MDP)      | **部分可观测马尔可夫决策过程 (POMDP)**  |
| **状态空间** | 单一提示 (Prompt)         | **动态、持续变化的环境状态**           |
| **动作空间** | 生成文本                  | **文本 + 调用工具 + API请求**等多种行动 |
| **奖励信号** | 单一的最终评分               | **步骤级密集奖励 + 稀疏的最终奖励**      |
| **优化目标** | 单次输出的期望奖励             | **长期累积奖励的期望**，关注整个过程       |

### 核心能力

为了成为一个真正的自主智能体，Agentic RL 致力于赋予模型以下六大核心能力：

1. **规划 (Planning)**：能够拆解复杂任务，制定多步行动计划，并根据环境反馈动态调整。
2. **工具使用 (Tool Use)**：自主判断并调用外部工具，如搜索引擎、代码解释器或数据库。
3. **记忆 (Memory)**：在长期交互中保留关键信息，并学习识别哪些信息值得记住。
4. **推理 (Reasoning)**：根据任务需求，在快速的直觉推理和深度的链式推理间灵活切换。
5. **自我改进 (Self-Improvement)**：通过经验积累进行反思和自我修正，形成持续学习的闭环。
6. **感知 (Perception)**：能理解并处理图像、音频等多模态信息。


> [!caution] Agentic RL 在“物理层面”针对的是模型，但在“功能层面”是为了塑造智能体
> - **模型（Model）**：指大语言模型（LLM）本身的**神经网络权重**（即存储在服务器上的那组参数）。
> - **智能体（Agent）**：指 “模型 + 环境 + 工具” 组成的完整系统（包括模型、记忆模块、代码解释器、搜索引擎、以及与环境交互的循环机制）。
> 
> 基于这个区分，答案分为三个层次：
> 1. **物理层面**（训练对象）：**针对模型**
> 	- Agentic RL 在代码底层执行时，**反向传播（Backpropagation）的梯度是直接计算并更新模型神经网络里的权重参数的**。
> 		- 算法（如 PPO 或 GRPO）会根据一整条 Trajectory（轨迹）的最终回报，计算出 Loss（损失函数），然后调整模型的权重。
> 	- **结论**：你在训练日志里看到的“模型保存”（Checkpoint），保存的就是这个被强化学习调教过的模型本身。
> 2. **评估层面**（奖励对象）：**针对智能体**
> 	- 虽然更新的是模型参数，但**奖励信号（Reward）的来源和评估对象是整个智能体系统的表现**。
> 		- 模型仅仅输出文本（动作），但环境会执行这些文本（比如调用工具、运行代码、访问网页）。
> 		- 奖励机制不看“模型输出的文本是否优美”，而是看**“智能体系统完成任务的结果”**（比如：代码是否运行通过、是否成功订到票、是否在环境中获得高分）。
> 	- **结论**：模型参数是被动的“学生”，而整个智能体系统是那个参加“考试”的实体，考试分数（奖励）给的是智能体的整体表现。
> 3. **概念层面**（根本目的）：**为了“造就”智能体**
> 	- 这是最核心的认知转变：**如果不用 Agentic RL，模型只是一个“静态的知识库”；用了 Agentic RL 之后，模型才具备了“智能体性”（Agenticity）。**
> 		- 传统微调教的是模型“如何接话”（基于当前 Prompt 的下一个 Token 概率）。
> 		- Agentic RL 教的是模型“如何在动态环境中做决策”（基于当前状态，选择调用工具还是直接回答，以及调用哪个工具）。
> 	- 这就把模型从“大脑”升级为了拥有“手脚（工具）”和“记忆”的智能体。



## Trajectory

Trajectory（轨迹）指的是智能体（AI）从任务开始到结束，与环境交互所经历的一条**完整的状态-行动-奖励序列**。

### 数学构成

在强化学习中，一条轨迹（通常用希腊字母 $τ$ 表示）由以下元素按时间顺序组成：

$$
τ=(s_0​,a_0​,r_1​,s_1​,a_1​,r_2​,s_2​,…,s_T​,a_T​,r_{T+1}​)
$$

- **状态 (State, $s_t$​)**：智能体在某个时刻感知到的环境情况（例如：当前的用户提问、网页截图、或代码运行后的报错信息）。
- **动作 (Action, $a_t$​)**：智能体在这一步做出的决策（例如：生成一段思考、调用一次搜索引擎、执行一行代码）。
- **奖励 (Reward, $r_t$​)**：环境在智能体执行动作后给出的即时反馈信号（例如：代码是否运行成功、搜索是否返回了有效结果）。

### 具体实例

假设你让一个Agentic RL智能体帮你**预订一张去北京的机票**。它的一条完整轨迹（Trajectory）可能长这样：

1. **状态 $s_0$​**：用户提问“帮我订一张明天去北京的机票”。
2. **动作 $a_0​$**：智能体调用“航班查询API”。
3. **奖励 $r_1$​**：API返回数据成功（+0.1分）。
4. **状态 $s_1$​**：屏幕显示返回了 5 个航班选项。
5. **动作 $a_1$​**：智能体选择价格最低的航班并填入支付信息。
6. **奖励 $r_2​$**：填入成功（+0.1分）。
7. **动作 $a_2$​**：智能体点击“确认支付”。
8. **最终奖励 $r_3$​**：订票成功（+10分）。

**这条从第一步到最后一步的完整序列，就是一个 Trajectory。**

### 重要性

在传统监督学习中，我们只看最终答案；但在 Agentic RL 中，**Trajectory 是唯一的训练样本**，它的重要性体现在两个层面：

- **解决“信用分配”问题 (Credit Assignment)**：如果最终任务失败了（比如票没订成功），那问题出在哪一步？是因为API没调好，还是因为选错了航班？通过分析整条Trajectory，算法才能把“惩罚”或“奖励”精确地分配到导致成败的关键步骤上，而不是笼统地批评整个模型。
- **从稀疏奖励中学习 (Sparse Rewards)**：很多时候只有最后一步才有大奖励（如“订票成功”+10），中间步骤全是0。Trajectory记录了智能体为了拿到那个“+10”所走过的所有弯路和捷径，算法通过分析大量轨迹，就能学会那些“虽然当前奖励为0，但对最终成功至关重要”的策略（例如先查余票）。

### 关键区分：好的轨迹 vs 坏的轨迹

在训练Agentic RL时，模型会生成海量轨迹。算法（如PPO或GRPO）的核心工作，就是**对比不同轨迹的累积回报**：

- **Positive Trajectory（正轨迹）**：成功完成任务，累积奖励高。模型会被强化，下次更倾向于走这条路径。
- **Negative Trajectory（负轨迹）**：任务失败或陷入死循环（如反复报错无法恢复），累积奖励低。模型会被惩罚，减少走这条路的概率。

简而言之，**Trajectory 就是 AI 的“试错日记”**——Agentic RL 的所有学习，本质上都建立在对海量“试错日记”进行复盘和比较的基础上。这也正是它比普通单次响应模型更智能、更有“规划感”的根本原因。
