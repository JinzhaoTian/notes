NanoClaw 被看作是 OpenClaw 在安全方面的增强版替代方案，其核心设计理念是通过极简的代码和操作系统级别的隔离，来解决 AI Agent 在自主运行时可能带来的安全风险。

## 核心架构

NanoClaw 遵循严格的职责分离原则，宿主机只负责调度和通信，而实际的 AI 推理和任务执行则在隔离的容器中进行：
1. **核心调度器（Orchestrator）**：
    - **技术实现**：这是一个用 TypeScript 编写的单 Node.js 进程。
    - **核心职责**：它像一个“指挥中心”，负责轮询 SQLite 数据库检查新消息、管理消息队列、决定何时为哪个群组启动或停止容器，并通过文件系统与容器进行通信。
    - **极简体现**：整个核心逻辑只有约 500 到 4000 行代码，设计目标是在 8 分钟内可以被完全理解。它没有使用复杂的消息中间件，一切从简。
2. **数据存储（SQLite）**：
    - **技术实现**：使用 SQLite 作为中心化的数据存储。
    - **核心职责**：存储所有消息、定时任务、群组注册信息和系统状态。它被设计为“真相的唯一来源”（Single Source of Truth）。
    - **设计优势**：选择 SQLite 而非 Redis 或专业数据库，是为了实现**零外部依赖**，简化部署和运维。
3. **隔离容器（Isolated Containers）**：
    - **技术实现**：这是 NanoClaw 安全性的基石，每个 AI Agent 都在自己独立的 Linux 容器中运行。在 macOS 上，它利用系统自带的 Apple Container 以获得高性能；在 Linux 上，则使用 Docker。
    - **核心职责**：容器内只运行 AI Agent Loop 和 Anthropic 的 Agent SDK。它只能访问宿主机**显式挂载**进来的、属于特定群组的目录，对系统其他部分完全不可见。
    - **安全意义**：这意味着即使 AI 被恶意提示词“劫持”，它的所有破坏行为（如删除文件、运行恶意脚本）都将被**严格限制在这个容器内部**，无法触及宿主机和其他敏感数据。
4. **技能引擎（Skills Engine）**：
    - **技术实现**：这不是一个后台服务，而是一种**通过 AI 来修改自身代码的扩展机制**。
    - **核心职责**：当你需要新功能（如集成 Telegram）时，只需运行一个类似 `/add-telegram` 的命令。NanoClaw 会调用 Claude Code，**自动重写项目源代码**来添加这个功能。
    - **设计优势**：NanoClaw 实例将只包含你真正需要的功能代码，而不是像传统软件那样，为了一个功能而携带一个庞大的、包含无数潜在漏洞的插件库。它通过三路合并等机制智能地处理代码修改，确保过程的可靠性。

## 三路合并：让 AI 自己修改代码

> [!tip] 三路合并（Three-way merge）
> 三路合并（Three-way merge）是一种自动合并不同版本修改的算法，其核心思想是：不直接比较两个新版本，而是引入它们的“共同祖先”作为参考，从而智能地判断如何合并。
> 

在 NanoClaw 中，这个算法被用在了一个非常前沿的地方——作为其“技能引擎”的核心，让 AI 能够安全、智能地修改自己的代码来添加新功能。

这个过程同样可以被映射为三路合并：
- **共同祖先（Base）**：NanoClaw 当前稳定、干净的源代码。
- **左版本（Left）**：NanoClaw 的源代码，加上你想要添加的新功能（例如 `/add-telegram`）的代码片段。这可以看作是你“期望”的最终状态。
- **右版本（Right）**：AI（如 Claude Code）根据你的指令，独立生成的、用于添加 Telegram 功能的一段完整代码。这是 AI 提议的修改方案。

当你在 NanoClaw 中运行 `/add-telegram` 命令时，背后发生的是：

1. **AI 理解指令并生成代码**：Claude Code 会分析你的需求，并生成一份实现 Telegram 集成的代码提案（这就是“右版本”）。
2. **执行三路合并**：NanoClaw 的核心调度器会启动一个“三路合并”过程，将“共同祖先”（原始代码）、你的“期望状态”（左）和AI的“代码提案”（右）进行合并。
3. **智能合并与冲突处理**：
    - 如果 AI 的提案和你期望的修改不冲突（比如修改的是不同函数或代码块），三路合并就会自动将两者结合，生成最终的、包含了新功能的代码。
    - 如果两者修改了同一处地方（例如，都修改了同一个配置文件），就会产生“冲突”。此时，NanoClaw 可能会通过三路合并来智能地处理，尝试将修改融合在一起，而不是简单地报错。这种将“补丁”作为合并对象的能力，比传统的补丁应用更强大，因为它拥有更完整的上下文信息。
4. **更新代码库**：合并成功后，NanoClaw 的源代码就被更新了，新技能正式生效。

通过这种方式，NanoClaw 不仅实现了功能的动态扩展，还保证了整个过程的安全性和可审计性，因为所有的修改都是基于一个已知的、干净的“共同祖先”进行的，并且可以通过“三路合并”的日志清晰地追溯。

## 安全机制

1. **操作系统级隔离**：如上所述，容器化是第一道也是最坚固的防线。
2. **最小权限原则**：容器内的 AI 代理只能访问通过白名单明确挂载的目录。像 `~/.ssh`、`~/.aws` 等敏感路径会被自动屏蔽。同时，对于非主控制群组，挂载的目录被强制设置为只读，防止 AI 篡改关键数据。
3. **可审计的代码**：整个系统只有几千行代码，使得开发者（或另一个 AI ）能够轻松地审计整个项目的安全性，发现潜在的后门或漏洞。这解决了 OpenClaw 这类庞大代码库“无人能审”的困境。
4. **内部权限控制**：即使是容器内的 AI，其能调用的工具也被严格限制在一个安全集内（如 Bash 、文件操作）。同时，通过 IPC 机制，只有主控制群组才有权限执行注册新群组等高危操作，防止权限滥用。
