## 主流框架

| 框架名称                                | 核心定位 / 设计哲学   | 一句话选型建议                                     |
| ----------------------------------- | ------------- | ------------------------------------------- |
| **LangChain / LangGraph**           | 模块化底座 + 状态图编排 | 追求**生产级稳定性和精细控制**的开发者首选。                    |
| **AutoGen (AG2)**                   | 对话驱动的多智能体协作   | 需要**快速验证多智能体交互**或进行学术研究的团队。                 |
| **CrewAI**                          | 角色化的团队协作框架    | **快速搭建标准化流程**（如市场调研、内容创作）的原型。               |
| **Microsoft Semantic Kernel**       | 企业级、多语言SDK    | 身处 **.NET / Azure 技术栈**，需要与企业现有架构深度集成的团队。   |
| **AgentScope (阿里)**                 | 企业级全流程框架      | **金融、政务等对安全、监控要求极高**的复杂企业系统。                |
| **LlamaIndex**                      | 数据（RAG）中心化框架  | 核心任务是**与私有数据深度交互**（如文档问答、知识库）的智能体。          |
| **OpenAI Agents SDK**               | 官方原生工具链       | 已锁定**OpenAI生态**，希望用最少代码实现搜索、代码执行等功能的开发者。    |
| **低代码平台 (Coze / Dify / Voiceflow)** | 可视化、快速交付      | **业务团队、产品经理**快速验证想法，或需要**快速上线标准化客服、助手**的场景。 |

| 对比维度         | LangChain/LangGraph           | AutoGen          | CrewAI          | AgentScope   |
| ------------ | ----------------------------- | ---------------- | --------------- | ------------ |
| **架构类型**     | 库（模块化）+ 图编排框架                 | 框架（对话驱动）         | 库（角色驱动）         | 平台（全流程）      |
| **主要语言**     | Python, JavaScript/TypeScript | Python           | Python          | Python       |
| **状态控制**     | **极强**（基于图的状态管理）              | 较弱（依赖对话流）        | 中等（基于任务流程）      | 中等（结构化组织）    |
| **多智能体协作模式** | 精确、可编程的图结构                    | 灵活、自发的对话式        | 角色化、流程化团队       | 结构化、稳健的组织架构  |
| **工程成熟度**    | 高（生产级标准）                      | 高（但API变动风险需留意）   | 中（原型快，生产有挑战）    | 极高（企业级设计）    |
| **核心优势**     | 500+集成，**控制力与灵活性兼备**          | 多智能体**研究/实验**效率高 | **上手最快**，代码简洁直观 | 可视化、分布式、安全沙箱 |
| **核心局限**     | 学习曲线陡峭                        | 成本较高，状态流转不够精细    | 处理复杂动态流程能力有限    | 学习成本略高于轻量级框架 |
| **典型成本**     | 低 ($0.18/查询)                  | 中 ($0.35/查询)     | 低 ($0.15/查询)    | 信息缺失         |



| 维度          | **Claude Code (Anthropic)**                   | **Codex (OpenAI)**                    |
| ----------- | --------------------------------------------- | ------------------------------------- |
| **核心框架/模式** | 轻量级CLI工具 + 模型驱动                               | 应用服务器架构 + 智能体循环                       |
| **设计哲学**    | Unix哲学：做简单的事，可组合的基元                           | 企业级集成：统一的API层，支持多客户端                  |
| **技术栈**     | Bun, CommanderJS, **React Ink** (终端渲染)        | 自定义API层 (Responses API)，**智能体循环**引擎   |
| **上下文管理**   | **自动压缩**：让模型总结对话历史                            | **智能压缩**：专有"compaction"技术，支持24小时+连续运行 |
| **工具调用策略**  | **Agentic Search**：优先使用标准工具 (grep/glob) 而非RAG | **Shell优先**：主要通过Shell命令交互，辅以沙箱环境      |
| **对MCP的态度** | **原生支持**：内置MCP服务器，支持三层配置管理                    | **评估后拒绝**：认为MCP缺乏丰富的会话语义，但可选支持        |
| **安全模型**    | 文件读默认允许，写/执行需显式授权                             | 沙箱化执行环境，混合主动交互设计                      |
