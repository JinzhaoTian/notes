在 Vulkan 中，**Render Pass** 是一个核心的、结构化的对象，它描述了渲染操作期间所使用的帧缓冲区的附件（如颜色、深度、模板附件）以及这些附件将被如何使用。

一个 Render Pass 由一个或多个 Subpass 组成：

1. **Render Pass**：定义整个渲染过程所需的全部附件。
2. **Subpass**：定义在渲染过程中的一个特定阶段。
	- 每个 Subpass 会指定它使用哪些附件（作为输入、颜色输出、深度/模板输出），并且 Subpass 之间可以存在依赖关系（例如，一个 Subpass 必须在另一个 Subpass 完成后才能开始）。


## 主要特点

1. **附件描述**：明确声明将使用哪些颜色、深度和模板附件。
2. **负载操作**：定义在 Render Pass 开始时如何处理附件内容（例如，清除、保留、不关心）。
3. **存储操作**：定义在 Render Pass 结束时如何处理附件内容（例如，存储到内存、不关心）。
4. **子流程和依赖关系**：允许将复杂的渲染分解为多个阶段，并精确控制它们之间的内存和执行依赖。这对于 Tile-Based GPU 架构（如手机上的 Adreno、Mali）至关重要，因为它使得驱动程序能够进行深度优化，将整个 Render Pass 的数据尽可能长时间地保存在快速的片上缓存中。
5. **帧缓冲区兼容性**： FrameBuffer 对象是根据 Render Pass 的蓝图创建的，Vulkan 可以检查 FrameBuffer 是否与 Render Pass 兼容。
