B-REP（Boundary Representation，边界表示法）是三维几何建模中最核心的一种实体表示方法，其通过描述物体的边界来精确定义一个三维形体。

## 核心组成

B-REP 模型包含两大类信息，两者结合才能完整定义一个物体：

1. **几何信息**：描述形状的具体数据（位置、大小、曲线曲面的方程）
	- **点**：三维空间中的坐标 (x, y, z)
	- **曲线**：边的实际形状，如直线、圆弧、贝塞尔曲线
	- **曲面**：面的实际形状，如平面、圆柱面、NURBS 曲面
2. **拓扑信息**：描述这些几何元素之间的连接和邻接关系
	- **体 (Body)**：完整的实体或片体
	- **壳 (Shell)**：一组连续的面（实体有外、内壳）
	- **面 (Face)**：围成体的表面，是曲面上有界的一部分
	- **环 (Loop)**：面上封闭的边界回路（外环通常逆时针，内环顺时针）
	- **边 (Edge)**：面的边界，由一条曲线和两个顶点界定
	- **顶点 (Vertex)**：两条或多条边的交点

一个立方体用 B-REP 表示，就是：6个平面（几何），每个面由4条直线边（几何）首尾相连成环（拓扑），12条边交汇于8个顶点（拓扑），最终形成一个完整的体。

## 优缺点

1. **优点**
	- **表达能力强**：可以精确描述非常复杂的自由曲面，如汽车外壳、航空叶片。
	- **便于后续操作**：可以直接对面、边进行操作，如局部圆角、倒角、抽壳、装配约束等，非常灵活。
	- **显示和出图方便**：因为直接存有边界信息，渲染和生成工程图时提取轮廓线非常高效。
2. **缺点**
	- **数据量大**：需要存储完整的几何和拓扑关系，文件比体素法或CSG树要大。
	- **不保证始终有效**：复杂操作后可能出现面破裂、边悬空等拓扑错误，需要健壮的算法来修复。
	- **建模过程较复杂**：通常需要拉伸、旋转、扫掠、放样等高级特征来间接构建底层B-REP数据。

## 常用场景

B-REP 是几乎所有主流 CAD/CAM/CAE 软件的基础内核：

- **Parasolid** (西门子，用于 SolidWorks、NX)
- **ACIS** (达索系统，用于 AutoCAD、Inventor)
- **CGM** (达索系统，用于 CATIA)
- **OpenCASCADE** (开源几何内核，用于 FreeCAD)

当你进行零件设计、生成数控加工刀路、做有限元网格剖分时，背后都是由 B-REP 模型提供精确的几何边界信息。

### CAD

在 CAD 领域，B-REP 是整个系统的**数字基底**和**通用语言**。

1. B-REP 是**精确几何的“唯一真实来源”**
	- **存储最终结果**：无论设计师在界面上用了多少层特征（拉伸、打孔、圆角），B-REP 模型存储的都是物体此刻最完整、最精确的最终边界。它定义了实际存在的那个实体。
	- **表达能力的天花板**：只有 B-REP 能精确描述那些复杂的工业曲面（如汽车外壳的 A 级曲面、航空发动机的叶片）。基于网格或体素的模型，都只是近似，而 B-REP 是精确定义。
	- **承载设计意图**：B-REP 的拓扑结构暗含了“制造特征”。一个“通孔”在 B-REP 中不只是一个洞，而是一个由具体圆柱面构成的内环，这直接对应了钻头会切削掉的区域。

2. B-REP 是**所有建模操作的“底层执行者”**：在 CAD 软件里的每一次操作，本质上都是在让内核修改 B-REP 数据。
	- **特征树的幕后推手**：我们看到的“拉伸”、“旋转”特征，只是操作指令。当你拖动一个特征的参数时，几何内核（如 Parasolid、ACIS）在后台飞速进行布尔运算、曲面求交等操作，实时计算并刷新出一个新的 B-REP 模型。
	- **局部操作的根基**：倒圆角、拔模、抽壳这些极难用其他方式表达的复杂操作，是直接作用于 B-REP 的拓扑元素（边和面）上的。“给这条边倒个圆角”，正体现了 B-REP 能让软件精准定位和修改物体任意局部的独特能力。

3. B-REP 是**打通全流程的“数据枢纽”**：一个 B-REP 模型能被创建出来只是第一步，它能被整个产品生命周期里的各种软件无障碍地读取和利用，这才是更大的价值。
	- **生成工程图**：点击“投影视图”，软件就是瞬间计算 B-REP 所有边的轮廓线。
	- **对接 CAM 加工**：数控编程时，刀轨必须精确地贴合在 B-REP 定义的曲面或偏置面上，公差要求从这里产生。
	- **支持 CAE 仿真**：有限元分析前划分网格，理想的流程是先基于 B-REP 的精确曲面生成高质量网格，而不是在低精度的近似模型上分析。
	- **进行装配与检查**：干涉检查、间隙测量，计算的依据都是 B-REP 模型上点到面、面到面的精确距离。

4. B-REP 是**参数化设计中“关联性”的基石**：当模型参数改变后更新，系统如何知道该把倒角加在哪个边上？这依赖于 B-REP 的拓扑命名与追踪机制。
	- **智能识别**：系统会赋予 B-REP 中的每个面、每条边一个持久的名字。当模型重建时，它通过对比拓扑变化来识别出“这条边就是上次倒角的边”，然后把倒角特征准确地重新应用上去。没有这个，参数化驱动就会混乱崩溃。

在目前及可预见的未来，**对于主流的精确工程 CAD 软件，B-REP 是不可避免的底层核心**。这源于 B-REP 具备一个其他表示法无法同时达成的“三角能力”，而这恰恰是工程制造的硬性要求：

1. **精确性无法被妥协**  
	- 工业零件必须被精确制造。B-REP 使用 NURBS 曲面、直线、圆弧等数学方程来精确定义边界。而多边形网格只是在近似这些形状。你不能把一张由无数小三角面片组成的“近似圆形”图纸交给数控机床，去加工一个高精度的轴承座。
2. **能够进行复杂的局部操作**  
	- 倒圆角、拔模、抽壳等操作，需要软件能在“某条精确的边”或“某个精确的面”上执行，这强依赖于 B-REP 的拓扑结构。其他模型里，实体内部是空的，根本没有“边”和“面”的稳定标识与邻接关系，无法完成这类操作。
3. **作为全生命周期的数据枢纽**  
	- 从工程图生成、到 CAM 加工、再到 CAE 仿真，所有这些下游工序都在向 B-REP 索取精确的几何定义。比如，碰撞干涉检查中测量两个零件之间的距离，必须基于精确曲面才能得出可信的数值。

只要一个软件的核心目标是**制造出精确的物理零件**，它就绕不开 B-REP。


## CSG

B-REP 常和 CSG（构造实体几何法）一起讨论：

- **CSG** 通过简单体素（方块、圆柱等）和布尔运算的组合历史来隐式定义形体，数据结构是一棵树，但不存储最终的边界细节。
- **B-REP** 存储的是显式的、最终的边界结果。

现代系统通常混合使用：用户用 CSG 的方式（特征树）进行设计，内核实时计算并更新底层的 B-REP 模型。


## 几何内核库

开发 CAD 软件时，目前可选的库主要分为商业级和开源两类，各自定位差异很大。

### 商业级几何内核

这类内核经过数十年工业验证，稳定、高效，并提供技术支持，是开发专业商用 CAD 软件的首选。但授权费用高，且通常需按版本支付版税。

|内核|开发商|典型客户/应用|特点与建议|
|---|---|---|---|
|**Parasolid**|Siemens PLM|SolidWorks, NX, Solid Edge, Onshape|**行业事实标准**，功能最全面、最稳定，数据交换格式 x_t 通用性极强。适合开发大型、对标主流中高端的软件。授权门槛高，会严格评估客户背景。|
|**ACIS**|Dassault Systèmes (Spatial)|AutoCAD, Inventor, Cimatron|历史最久，文档丰富，有灵活的组件授权（如只买基础内核+高级曲面）。对中小企业更友好，生态成熟。适合开发通用机械、建筑类或中端产品。|
|**CGM**|Dassault Systèmes|CATIA, SolidWorks 部分功能|以强大的曲面造型和特征建模著称，是 CATIA 的核心动力。适合开发对标 CATIA 的顶级高端软件，尤其是汽车、航空曲面领域。授权策略较为封闭。|

另外，**PTC 的 Granite** 内核基本不外授，Autodesk 的 **ShapeManager**（从 ACIS 分支）也已内部化，均无需考虑。

### 开源几何内核

如果预算有限，或想先快速搭建原型，开源内核几乎是唯一选择。

1. **OpenCASCADE Technology**
	- **当前版本**：7.x 系列，持续更新。
	- **许可证**：LGPL 2.1（允许动态链接用于闭源商业软件，静态链接需开放你的修改部分代码）。
	- **功能覆盖**：完全具备一个完整 B-REP 内核所需的一切：
	    - 完善的拓扑/几何库，支持点、线、圆、NURBS 曲线曲面。
	    - 完整的建模操作：拉伸、旋转、放样、扫描、布尔运算、倒角、抽壳、拔模等。
	    - 丰富的数据交换接口（STEP, IGES, STL, glTF 等）。
	    - 内置可视化模块（基于 OpenGL）。
	- **代表项目**：FreeCAD、CadQuery、SALOME 都基于它。
	- **优劣**：功能强大，但 API 复杂、文档相对欠佳，部分复杂操作（如高级倒角、抽壳）的算法稳定性弱于商业内核，需要团队投入精力消化和优化。

围绕 OpenCASCADE 的生态库能极大加速开发：
- **pythonOCC**：提供了完整的 Python 封装，适合算法原型验证和脚本化应用。
- **CadQuery**：在 OCCT 基础上构建了极富创意的 Python 流体 API，适合电气、机械自动化领域快速开发。
- **FreeCAD**：虽然是个完整软件，但其模块化架构允许你复用它的核心模块（如零件设计、草图、网格工作台）来构建自己的软件。

2. **其他小型/实验性开源内核**：这些不适合作为主力工程内核，但可用于学习或特定场景：
	- **SolveSpace**：一个独立小型 CAD 软件的内核，用 C++ 编写。拥有完整的 NURBS 曲面和约束求解器。代码紧凑精炼，非常适合学习内核实现原理，但尚不足以支撑大型项目。
	- **Fornjot**：Rust 语言编写的新兴实验性内核，主打前沿技术，长期不成熟。
	- **CGAL**：计算几何算法库，有 3D 布尔运算和 NURBS 处理能力，但**它不是一个完整的实体建模器**，没有拓扑管理、特征树等，更适合算法研究而非应用开发。
	- **BRL-CAD**：主要为 CSG 表示，带部分 B-REP 支持，偏向军事和工程分析，非常古老。


## 二、三维差异

二维和三维 CAD 虽然都用 B-REP 这个概念，但维度的差异带来了根本性的不同：
- **三维 B-REP**：定义的是一个**有体积的实体**，由封闭的曲面外壳围成。
- **二维 B-REP**：定义的是一个**有面积的封闭区域**，由封闭的曲线边界围成。

| 维度       | 三维 B-REP (实体建模)                    | 二维 B-REP (草图或轮廓)                 |
| -------- | ---------------------------------- | -------------------------------- |
| **描述对象** | 一个封闭的**体** (Solid) 或开放的片体 (Sheet)  | 一个或多个封闭的**区域** (Region)          |
| **顶级拓扑** | **体** → 壳 → **面** → 环 → **边** → 顶点 | **区域** → **环** → **边** → 顶点      |
| **几何基元** | **曲面** (如 NURBS 曲面)                | **曲线** (如直线、圆弧、NURBS 曲线)         |
| **核心难点** | 曲面求交、曲面延伸与裁剪、复杂的拓扑修复               | 曲线的封闭性、自相交检测、环的包含关系判断            |
| **布尔运算** | 计算量巨大，是内核稳定性的试金石                   | 相对成熟和稳定，是二维引擎的标配                 |
| **典型应用** | 零件设计、装配、数控加工、CAE 仿真                | 草图轮廓、PCB 走线、DWG 工程图中的截面填充、激光切割路径 |

1. **拓扑结构**：从“面”降维到“环”，最根本的区别，决定了数据结构的组织方式。
	- **三维 B-REP 中，面 (Face) 是核心。** 一个立方体由 6 个**面**组成，每个面是**曲面**上的一个有界区域。其边界由环 (Loop) 定义，而环由边 (Edge) 首尾相连而成。体是面的集合。
	- **二维 B-REP 中，环 (Loop) 是核心。** 一个圆面没有厚度，它由一个叫“区域 (Region)”的顶级拓扑元素表示。这个区域由一个外**环**定义，如果有孔，则还有一个或多个内环。这里没有“面”，只有被环包围的平铺区域。

2. **几何基元**：从“曲面”降维到“曲线”
	- **三维 B-REP** 的**边 (Edge)** 由一条空间**曲线 (Curve)** 定义，这条曲线深深附着在一个**曲面 (Surface)** 上。边本质上是用一条曲线去裁剪一个曲面得到的边界。这是一个强耦合的复杂关系。
	- **二维 B-REP** 的**边 (Edge)** 只由一条平面**曲线 (Curve)** 定义。它不附着在任何曲面上，因为整个二维世界就是一个巨大的 XY 平面。

3. **布尔运算**：复杂度的分水岭
	- **二维布尔运算（求并、交、差）**：本质上是在平面上求曲线交点，然后重新组织环的包含关系。算法（如 Greiner-Hormann 算法）非常成熟，速度快，稳定性高，能轻松处理带大量孔洞的复杂图形。这正是 PCB 设计、激光切割排版软件的基础。
	- **三维布尔运算**：困难程度跃升了几个数量级。
	    - **曲面求交 (SSI)**：两个 NURBS 曲面的交线计算极其复杂，涉及高次非线性方程、奇点处理，是几何内核最核心、最容易出错的模块。
	    - **拓扑重建**：求出交线后，需要用这些交线去裁剪每个参与运算的曲面，然后判断哪些面要保留，哪些要丢弃，最后重新缝合成一个有效的封闭体。这个过程极易产生微小的缝隙、碎片面，导致运算失败或产生无效实体。
