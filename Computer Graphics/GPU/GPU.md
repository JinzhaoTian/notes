GPU 管线分为 **逻辑阶段**（从应用程序到最终像素）和 **硬件映射**（各阶段在 GPU 具体单元上的执行方式）两个维度。

## 一、管线总览与术语定义

**图形管线（Graphics Pipeline）**：将 3D 场景描述（顶点、纹理、光照、摄像机）转换为 2D 图像的一系列有序处理阶段。每个阶段对输入数据执行特定变换，并将结果传递给下一阶段。

**两种主流管线模型**：
- **即时模式（Immediate Mode）**：传统桌面 GPU 架构，每个图元（三角形）立即光栅化并着色，典型代表为 NVIDIA/AMD 桌面 GPU
- **图块延迟渲染（Tile-Based Deferred Rendering, TBDR）**：移动端和部分桌面 GPU（如 Apple M 系列），将屏幕划分为若干图块，每个图块独立完成完整管线，显著节省带宽

下文以 **即时模式 + 现代可编程管线**（Direct3D 12 / Vulkan 风格）为主线，必要时标注 TBDR 差异。


## 二、完整管线阶段拆解

管线分为 **九个逻辑阶段**，其中 **蓝色为可编程阶段**（开发者编写着色器），**橙色为固定功能阶段**（GPU 硬件自动执行，配置而非编程）。

### 阶段 1：输入装配（Input Assembler, IA）— 固定功能

**功能**：从顶点缓冲区读取顶点数据，根据索引缓冲区组装图元（三角形、线段、点）。

**关键操作**：
- **顶点获取**：从显存中的顶点缓冲区读取顶点属性（位置、法线、UV、颜色等）
- **索引处理**：可选地使用索引缓冲区，支持图元复用（减少顶点存储）
- **图元拓扑**：解释顶点序列的几何含义，包括：
  - 点列表（Point List）
  - 线段列表/线段带（Line List / Line Strip）
  - 三角形列表/三角形带（Triangle List / Triangle Strip）
  - 带邻接的图元（用于几何着色器）

**输出**：顶点流（带有拓扑结构）送入顶点着色器。

### 阶段 2：顶点着色器（Vertex Shader, VS）— 可编程

**功能**：对每个顶点独立执行，完成坐标变换与逐顶点属性计算。

**强制性操作**：
- **齐次坐标变换**：将顶点从模型空间变换到裁剪空间：
  
$$ 
  P_{clip} = P_{object} \times M_{model} \times M_{view} \times M_{projection}
$$
  其中 $M_{model}$ 为模型矩阵，$M_{view}$ 为视图矩阵，$M_{projection}$ 为投影矩阵（透视或正交）

**可选操作**：
- 逐顶点光照计算（传统 Gouraud 着色）
- 顶点动画（蒙皮骨骼变换）
- 纹理坐标生成或变换
- 法线变换与归一化

**执行模型**：
- 每个顶点独立，无数据依赖
- 高度并行，GPU 以 warp/wavefront 为单位调度
- 输出顶点属性（位置 + 其他属性）传递至下一阶段

### 阶段 3：曲面细分（Tessellation）— 可选，包含三个子阶段

曲面细分用于将粗粒度模型动态细分为更细密的三角形网格，适用于视点相关细分（地形、LOD）、平滑曲面细分（Catmull-Clark、PN 三角形）等场景。

#### 3.1 外壳着色器（Hull Shader, HS）— 可编程

**功能**：为每个控制点或每个面片配置细分因子（Tessellation Factors）。

**关键任务**：
- 计算边缘细分因子（Edge Tessellation Factor）和内部细分因子（Inside Tessellation Factor）
- 可选地修改控制点数据

#### 3.2 曲面细分器（Tessellator）— 固定功能

**功能**：根据外壳着色器传递的细分因子，在域内生成细分后的顶点 UVW 坐标（重心坐标或矩形坐标）。

- 支持三种域（Domain）：三角形（重心坐标）、四边形（矩形坐标）、等值线（Isoline）
- 输出原始细分图元（三角形或四边形 patch）

#### 3.3 域着色器（Domain Shader, DS）— 可编程

**功能**：接收曲面细分器生成的 UVW 坐标和外壳着色器传递的控制点，计算细分后的最终顶点位置。

- 典型应用：根据 UVW 参数计算曲面（如 Bezier 曲面、NURBS）位置
- 输出完整的顶点属性，类似顶点着色器

### 阶段 4：几何着色器（Geometry Shader, GS）— 可编程，可选

**功能**：对每个图元（三角形、线段、点）执行，可以：
- **改变图元类型**：将一个点扩展为多个三角形（例如粒子系统生成广告牌）
- **销毁图元**：丢弃不符合条件的图元（视锥体裁剪的早期版本）
- **生成新图元**：输出最多 1024 个顶点（D3D 上限），构成零个或多个新图元

**典型应用**：
- 爆炸效果（将三角形沿法线分裂为多个小三角形）
- 草叶生成（从线段生成复杂几何）
- 阴影体生成（阴影锥算法）

**性能警告**：几何着色器会严重破坏相邻顶点数据的并行性，且输出膨胀率高，通常应避免使用，改用网格着色器（Mesh Shader）或直接在其他阶段实现。

### 阶段 5：图元装配（Primitive Assembly）— 固定功能

**功能**：将顶点流组装为完整的图元（三角形、线段）。

**关键操作**：
- **裁剪（Clipping）**：将超出视锥体（平截头体）的图元部分裁剪掉，生成新的边界顶点
- **透视除法**：将齐次坐标 $(x, y, z, w)$ 转换为标准设备坐标（NDC）：
$$
x_{ndc} = x / w, \quad y_{ndc} = y / w, \quad z_{ndc} = z / w
$$
  
  其中 NDC 的范围为 $[-1, 1]$ 或 $[0, 1]$ 取决于 API

- **背面剔除（Back-face Culling）**：根据三角形绕序（顺时针或逆时针）丢弃背向摄像机的三角形，可配置

**输出**：屏幕空间中的二维三角形（带深度值）。

### 阶段 6：光栅化（Rasterization）— 固定功能

**功能**：将矢量三角形转换为片元（fragment）集合，每个片元对应于屏幕上可能被覆盖的像素。

**子阶段**：

#### 6.1 边缘遍历（Edge Walking）或边缘方程（Edge Equation）

现代 GPU 通常使用**边缘方程法**：对于屏幕空间中的三角形 $(v_0, v_1, v_2)$，计算每个像素中心到三条边的有向距离 $e_0(x,y)$, $e_1(x,y)$, $e_2(x,y)$ 。若所有 $e_i(x,y) \ge 0$（或 $\le 0$ 取决于绕序），则该像素被覆盖。

#### 6.2 多重采样（MSAA）处理

若启用多重采样抗锯齿，每个像素包含多个采样点（如 4x, 8x）。光栅器独立判断每个采样点是否被三角形覆盖。

#### 6.3 覆盖与深度测试前置（Early Depth Test）— 可选优化

在片元着色器执行前，可进行深度测试（Early-Z），若片元深度大于当前深度缓冲区值，直接丢弃，避免执行昂贵的片元着色器。

#### 6.4 属性插值

为每个片元计算顶点属性的重心坐标插值系数 $(\alpha, \beta, \gamma)$，用于后续片元着色器获取连续的纹理坐标、法线等。

**输出**：一个或多个片元，每个片元包含：
- 屏幕位置 $(x, y)$
- 深度值 ($z$) —— 插值后的
- 一组插值属性（纹理坐标、颜色、法线）

### 阶段 7：片元着色器（Fragment Shader, FS）— 可编程

**功能**：对每个片元独立执行，计算最终像素颜色和深度值。

**输入**：
- 光栅化器插值的属性（纹理坐标、法线、顶点颜色）
- 统一变量（Uniforms）：光照参数、纹理对象、材质属性等
- 纹理采样结果：通过纹理单元（TMU）读取

**典型操作**：
- **纹理采样**：根据插值 UV 坐标从纹理中读取颜色（支持滤波、Mipmap、各向异性）
- **逐像素光照**：Phong、Blinn-Phong、PBR（基于物理的渲染）模型
- **透明度测试**：根据 alpha 值 discard 片元
- **像素级效果**：凹凸映射、法线贴图、阴影采样

**关键限制**：
- 不能改变几何形状（不能移动片元位置）
- 不能访问相邻片元的数据（但通过某些扩展可进行有限访问）

**输出**：一个或多个颜色值（若启用了渲染目标数组）和新的深度值（可选）。

### 阶段 8：逐片元操作（Per-Fragment Operations）— 固定功能

**功能**：片元着色器输出后，执行一系列测试和混合操作，决定最终像素值。

**操作顺序**：

1. **像素所有权测试**（仅窗口系统）：确定当前像素是否属于 OpenGL 上下文窗口
2. **裁剪测试**：丢弃超出裁剪矩形范围的片元
3. **Alpha 测试**（已弃用，在片元着色器中用 discard 替代）
4. **模板测试（Stencil Test）**：将模板缓冲区值与参考值比较（$<$、$≤$、$>$、$≥$、$==$、$≠$），决定通过或丢弃
5. **深度测试（Depth Test，晚期）**：再次比较深度值（若未做 Early-Z）
6. **遮挡查询（Occlusion Query）**：统计通过深度测试的片元数
7. **混合（Blending）**：将片元颜色与帧缓冲区现有颜色按规则混合（标准混合方程）：

$$
C_{out} = C_{src} \times S + C_{dst} \times D
$$
   其中 $S$ 和 $D$ 为源因子和目标因子（如：SrcAlpha, OneMinusSrcAlpha）
8. **抖动（Dithering）**：在低精度显示设备上减少色带效应
9. **写入掩码**：按位控制写入 R/G/B/A 和深度通道

**输出**：最终像素写入帧缓冲区，以及深度/模板缓冲区的更新。

### 阶段 9：渲染输出合并（Render Output Merge）— 固定功能

**功能**：将来自不同渲染目标（Render Target）的多层输出合并为最终图像。

在延迟渲染（Deferred Rendering）管线中，片元着色器输出到多个渲染目标：
- MRT0：颜色
- MRT1：法线
- MRT2：材质参数（金属度、粗糙度）
- MRT3：深度 + 模板

这些数据在后期阶段由一个全屏四边形执行的片元着色器组合为最终屏幕图像。

## 三、硬件映射：阶段如何映射到 GPU 单元

现代 GPU 包含几种核心计算单元：

| 单元                 | 名称                                 | 负责阶段                        |
| ------------------ | ---------------------------------- | --------------------------- |
| **SM**             | Streaming Multiprocessor（流式多处理器）   | 所有可编程着色器（VS、HS、DS、GS、FS、CS） |
| **TPC**            | Texture Processing Cluster（纹理处理集群） | 纹理采样（片元着色器内部）               |
| **ROP**            | Render Output Unit（渲染输出单元）         | 逐片元操作（深度测试、模板测试、混合、写入帧缓冲）   |
| **Warp Scheduler** | 线程束调度器                             | SIMT 指令分发（所有可编程阶段）          |

### 3.1 SM 内部着色器执行

顶点着色器、片元着色器、几何着色器、计算着色器均由 SM 中的 CUDA 核心（或流处理器）执行：

- **指令发射**：Warp 调度器每个时钟周期从线程束中选择指令发射
- **操作数收集**：从寄存器文件读取
- **执行**：
  - 整数/浮点 ALU：大部分 CUDA 核心
  - 特殊函数单元（SFU）：sin、cos、log、pow 等
  - 加载/存储单元（LSU）：访问共享内存或全局内存
- **纹理采样**：通过纹理单元（TMU）与纹理缓存交互

### 3.2 固定功能单元映射

- **输入装配**：由专用硬件单元（IA）在命令处理器调度下执行
- **光栅化**：由光栅器（Rasterizer）单元执行，位于 SM 外部，通常每个 GPC 包含一个
- **逐片元操作**：由 ROP（渲染输出单元）执行，常位于内存控制器附近

### 3.3 延迟与缓存结构

各级缓存对应的管线阶段：

- **L1 缓存 / 共享内存**：SM 内部，供相同 SM 的线程共享，用于频繁访问的数据
- **纹理缓存**：只读，专为纹理采样优化（支持 2D 局部性）
- **常量缓存**：只读，存储统一变量
- **L2 缓存**：全芯片共享，缓解全局显存带宽压力


## 四、两种高级管线变体

### 4.1 图块延迟渲染（TBDR）

常见于移动 GPU（Apple GPU、ARM Mali、高通 Adreno）。

**核心思想**：将屏幕划分为小块（如 32×32 像素），每个图块（Tile）在芯片上独立完成从光栅化到混合的全流程，仅在边界时访问主显存。

**关键差异**：
- 在光栅化后引入**延迟着色**：先将片元存储到片上内存的图块缓冲区，而不是立即执行片元着色器
- 只有在同一图块内的所有三角形光栅化后，才开始片元着色
- 优点：片元着色器中的纹理读取可以合并，消除重复读取，显著节省带宽和功耗

### 4.2 网格着色器（Mesh Shader）管线

自 NVIDIA Turing 和 AMD RDNA2 引入，替代传统 VS/HS/DS/GS 管线。

**新模型**：
- **任务着色器（Task Shader）**：粗粒度剔除，生成任务负载
- **网格着色器（Mesh Shader）**：完全取代 VS 和 GS，直接输出三角形列表和顶点属性给光栅器

**优点**：
- 更高效的处理细分和剔除
- 减少 GPU 驱动开销
- 更灵活的可编程性


## 五、完整流程图

```
应用程序
   │ (Draw Call + 顶点/索引缓冲区)
   ▼
[输入装配]
   │ (图元拓扑)
   ▼
[顶点着色器] ──────────── 每顶点计算
   │
   ├─[外壳着色器] ─ (可选) 曲面细分配置
   │      ▼
   │  [曲面细分器] ───── 固定功能细分
   │      ▼
   │  [域着色器] ────── 计算细分顶点
   │
   ├─[几何着色器] ───── (可选) 图元扩展/丢弃
   │
   ▼
[图元装配 + 裁剪 + 背面剔除]
   │ (屏幕空间三角形)
   ▼
[光栅化]
   │ (片元 + 插值属性)
   ▼
[片元着色器]
   │ (RGBA + 深度)
   ▼
[逐片元操作：模板测试 → 深度测试 → 混合]
   │
   ▼
[帧缓冲区]
```


## 六、性能关键点总结

1. **Early-Z 优化**：在片元着色器前执行深度测试，避免无效片元着色器调用
2. **带宽瓶颈**：纹理采样、顶点缓冲区读取、深度/模板测试是主要显存访问来源，利用缓存和压缩（如 NVIDIA 的颜色压缩、深度压缩）降低带宽
3. **Tile 缓存**（TBDR）：移动端最重要的优化，尽可能在片上保留数据
4. **线程发散**：在片元着色器中，相邻像素的执行路径应尽量一致，避免 warp 发散（例如避免基于纹理内容的 discard 或复杂分支）
5. **渲染目标切换**：现代 GPU 优化了多渲染目标（MRT）的性能，但频繁切换渲染目标仍会刷新管线，应尽量批处理


## 七、与实时渲染 API 的对应

| 管线阶段 | OpenGL | Direct3D 11 | Direct3D 12 / Vulkan |
|---------|--------|-------------|----------------------|
| 顶点着色器 | Vertex Shader | Vertex Shader | VS |
| 曲面细分 | Tessellation Control/Evaluation Shader | Hull/Domain Shader | HS / DS |
| 几何着色器 | Geometry Shader | Geometry Shader | GS |
| 片元着色器 | Fragment Shader | Pixel Shader | PS |
| 逐片元操作 | 片段测试 + 混合 | 输出合并阶段 | OM |

这种对应关系有助于理解不同 API 的抽象层级差异，但底层硬件执行模型高度一致。
