在计算机图形学，特别是游戏开发（如Unity、Unreal）中，合批技术是一种优化手段，其核心目标是减少渲染过程中的“绘制调用”数量。

简单来说，合批就是把多个小的、独立的物体，合并成一个大物体，然后一次性交给GPU去绘制。

### 为什么要合批？

-   **核心问题：CPU 与 GPU 的通信瓶颈**
    每次 CPU 通知 GPU 绘制一个物体，都需要一次“绘制调用”（Draw Call）。为此，CPU 需要做大量准备工作，如收集数据、设置状态等。如果物体非常多，成千上万次 Draw Call 就会让 CPU 忙碌不堪，成为瓶颈。而 GPU 的绘制速度很快，但往往要空等 CPU 的指令，导致帧率下降。

-   **合批的解决方案**
    合批技术会把多个物体合并成一个大“数据包”，一次性发给 GPU。这样，Draw Call 从 N 次降为 1 次，CPU 的开销大幅降低。可以说，**合批就是用更少的次数，发送更多的数据**。

### 合批的核心原理

合批能实现，是因为它利用了 GPU 的“一次调用，绘制大量顶点”的能力。只要多个物体共享相同的渲染状态，理论上就可以合并。

**成功合批的必要条件：**

1.  **同一个材质**：共享同一份材质球、纹理、Shader。这是最基本、最重要的条件。
2.  **相同的渲染状态**：比如深度写入、混合模式、剔除模式等完全一致。
3.  **顶点数据可以合并**：将所有物体的顶点数据合并到一个大的顶点缓冲区中。

### 常见的合批技术

不同引擎的实现方式不同，以最主流的 Unity 为例，主要有三种：

| 技术名称                        | 工作原理                                                    | 优点                                   | 缺点                                            | 适用场景                    |
| :-------------------------- | :------------------------------------------------------ | :----------------------------------- | :-------------------------------------------- | :---------------------- |
| **静态合批** (Static Batching)  | 在**游戏运行前（构建时）**，将标记为“Static”且材质相同的静态物体（如建筑、地形）合并成几个大网格。 | 效率高，对 CPU 几乎没有运行时开销；能显著减少 Draw Call。 | 会增加内存占用和包体大小；合并后的物体无法单独移动或动态改变。               | 场景中大量不动的物体（墙壁、石头、道路）。   |
| **动态合批** (Dynamic Batching) | 在**游戏运行时（每一帧）**，自动将符合条件的小物体（如小道具、子弹）合并。                 | 灵活，物体可以移动；开发者无需太多手动操作。               | 限制很多（顶点数<300个、缩放必须一致、不能使用多材质等）；本身也有一定 CPU 开销。 | 大量小而移动的简单物体（如小金币、粒子效果）。 |
| **GPU Instancing** (实例化)    | 利用GPU硬件特性，**一次调用绘制同一个网格的多个实例**，每个实例可以有不同的位置、颜色等参数。      | 效率极高，尤其适合大量相同或相似的物体；比动态合批限制少，性能更好。   | 需要硬件支持（基本上现代GPU都支持）；Shader需要专门适配。             | 大量重复的物体（树林、草丛、同一怪物的群组）。 |

### 实际开发中的关键点

-  **优先使用静态合批**：对于关卡中的静态场景，这是最有效的方法。
-  **材质是核心**：两个物体只要材质不同（或材质实例参数不同），就**几乎不可能**合批。因此，**纹理图集**（把多张小图拼成一张大图）技术对合批至关重要。
-  **不是越多越好**：合批会创建更大的顶点缓冲区。如果合并一个包含十万顶点的巨型网格，一次Draw Call 却可能因为传输数据量巨大而卡顿。要根据目标平台（移动端更敏感）平衡。
-  **利用Profiler工具**：不要盲目优化。先用Unity Profiler、RenderDoc等工具，确认Draw Call确实是瓶颈，再应用合批技术。

### 总结

合批技术是一种用空间（内存）或灵活性换时间（CPU开销）的策略。它的核心就是：

**把能一起画的东西尽量放在一起画，减少CPU和GPU之间的无效沟通，从而提升渲染性能。**

在实际项目中，通常需要结合使用静态合批、动态合批、GPU Instancing，才能达到最好的优化效果。
