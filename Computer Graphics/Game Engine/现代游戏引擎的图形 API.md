主流游戏引擎并不会支持所有的图形 API，而是有选择地支持那些在目标平台上最流行和性能最优的解决方案。

| **平台**          | **Unity**                            | **Unreal Engine**                   |
| --------------- | ------------------------------------ | ----------------------------------- |
| **Windows**     | Direct3D 11/12, Vulkan, OpenGL Core  | 主要支持 **DirectX 11/12** 和 **Vulkan** |
| **macOS / iOS** | **Metal**, OpenGL Core (已弃用)         | 主要支持 **Metal**                      |
| **Android**     | **Vulkan**, OpenGL ES                | 主要支持 **Vulkan** 和 OpenGL ES         |
| **Linux**       | Vulkan, OpenGL Core                  | 主要支持 Vulkan                         |
| **游戏主机**        | 各平台专用API (如PS4/5, Xbox One/Series X) | 各平台专用API                            |

### 如何管理图形API

游戏引擎作为中间层，其首要任务是简化开发。因此，它们提供了一套统一的渲染接口，并帮你处理了不同图形API之间的底层差异。

以 Unity 为例，它在项目的 Player Settings 中提供了非常直观的图形API管理功能：
- **自动选择**：你可以勾选 Auto Graphics API，让 Unity 在运行时根据平台自动选择并使用最优的图形API
- **手动配置**：你也可以取消自动选择，手动为每个平台指定一个备选 API 的优先级列表。Unity 会使用列表中第一个可用的 API

### 为什么引擎不支持全部 API

这背后是基于技术、市场和效率的综合考量：

1. **平台与厂商策略**：不同操作系统和硬件厂商有自己主导的API。例如，Windows 上 DirectX 是事实标准；Apple 生态则全面推行自家的 Metal；而 Vulkan 作为跨平台新标准，在 Android 和 Linux 上地位日益重要。引擎会优先支持这些主场 API。
2. **开发与维护成本**：每一个图形API的支持都需要引擎团队投入巨大的资源进行开发、测试和优化。支持过多的、使用率低的 API 是不经济的。
3. **性能与特性**：现代引擎会积极拥抱像 **Vulkan**、**DirectX 12** 和 **Metal** 这样的**新一代低开销API**。它们能让开发者更接近底层硬件，从而更好地发挥GPU性能，实现更复杂的图形效果。相反，像旧版的 OpenGL 这样的传统 API，由于其设计和管理开销问题，正逐渐被边缘化甚至弃用。
