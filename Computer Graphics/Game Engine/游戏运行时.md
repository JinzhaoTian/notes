游戏运行时是游戏引擎不变的心脏，是一个在目标平台（PC、主机、手机等）上执行游戏逻辑、驱动所有子系统并维持游戏循环的框架。使用游戏引擎开发的游戏，在实际运行时需要启动游戏引擎的核心部分，但玩家看到的并不是一个完整的开发环境。

1. **开发阶段**：使用**游戏编辑器**（如 Unity Editor，Unreal Editor），这是一个功能完整的集成开发环境，包含场景视图、层级面板、项目设置、调试工具等。你在这里进行创作、编辑和测试。
2. **发布阶段**：你将项目构建成最终的可执行游戏，这个过程就像把源代码编译和打包。

从技术角度来说，游戏引擎本身不是像 Photoshop 那样的独立软件，而是作为代码库被编译进游戏里。

## 核心

一个典型的游戏运行时包含以下核心子系统：
1. **渲染系统（Rendering System）**：负责将2D/3D资源（模型、纹理）转换成屏幕上的像素。
2. **物理引擎**：模拟碰撞、重力、刚体/柔体动力学等。
3. **音频引擎**：管理声音的播放、混音和3D音效。
4. **脚本系统/逻辑层**：提供一种方式（如C#、Lua、视觉脚本）让开发者编写游戏规则和角色行为。
5. **资源管理器**：加载、管理、卸载游戏资源（模型、声音、动画等）。
6. **场景图/世界对象系统**：管理游戏世界中所有实体（Entity）或游戏对象（GameObject）的层次结构和生命周期。
7. **游戏循环**：这是运行时的核心脉搏，一个不断循环执行的流程，通常包括：
    - **处理输入**
    - **更新游戏状态**（物理、脚本逻辑等）
    - **渲染输出**

>[!info] 编辑器的配合
> 编辑器不是一个独立的工具，它是一个为运行时量身打造的、高度集成的开发环境。
> 1. **开发**：
> 	- 开发者主要在编辑器中拖拽物体、设置属性、连接逻辑，编辑器生成数据和配置文件。
> 2. **与运行时的关系**：
> 	- 紧密耦合，深度嵌入运行时
> 	- 编辑器包含了游戏运行时，并为其添加了开发工具（如 gizmo、调试绘制）。
> 3. **数据流**：
> 	- **双向、动态**：编辑器可以实时修改运行时的状态（如改变一个物体的位置），运行时也可以将数据反馈给编辑器（如显示调试信息）。
> 4. **核心功能模块**：
> 	- **场景编辑器**：可视化地布置游戏世界。
> 	- **属性检查器**：动态查看和修改对象属性。
> 	- **资产管道**：自动导入、处理、优化资源。
> 	- **可视化脚本** / **逻辑编辑器**：如 `Blueprint`，`Playmaker`。
> 	- **实时调试与剖析工具**：与运行时深度集成。


## 构建过程

当你点击 Build 或 Package Project 时，游戏引擎会做以下几件关键事情：
1. **代码编译**：将你的 C#、C++ 等脚本代码编译成机器或中间语言可以高效执行的代码。
2. **资源处理**：将你使用的所有资源（模型、纹理、音频、动画）转换成针对目标平台（PC、手机、主机）优化过的格式。
3. **引擎代码整合**：引擎并不会把它的全部代码都打包进去，它会进行**精简化**和**整合**。它会分析你的游戏实际用到了引擎的哪些系统（例如渲染、物理、音频、UI、网络），然后只将这些必要的部分和你的游戏代码、资源一起打包。

## 游戏运行时

当玩家双击你的游戏图标时：

1. **启动可执行文件**：运行的是你游戏自己的 `.exe`（Windows）或其他平台的可执行文件。
2. **初始化引擎运行时**：这个可执行文件首先会初始化并启动打包在内部的游戏引擎运行时，这个运行时是引擎的核心，负责：
    - 创建窗口。
    - 初始化图形 API（如 DirectX，Vulkan，Metal）。
    - 设置音频系统。
    - 加载你游戏中的第一个场景。
3. **执行游戏逻辑**：引擎运行时开始执行你编写的游戏脚本和逻辑，驱动整个游戏世界运转。

玩家完全不会看到 Unity 的启动画面或者 Unreal Editor 的界面（除非你特意把它们做成了游戏的加载画面）。他们看到的一切，都是由这个**整合在游戏内部的引擎运行时**所渲染和驱动的。
