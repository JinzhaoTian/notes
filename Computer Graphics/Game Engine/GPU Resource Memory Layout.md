GPU Resource Memory Layout（GPU 资源内存布局） 指的是数据在 GPU 显存中是如何组织和存储的，定义了 CPU 生成的数据和 GPU 理解的数据之间的映射规则。

> [!tip] 重要性
> - **性能关键**：GPU 是高度并行化的处理器，拥有成千上万个核心。为了高效地喂饱这些核心，数据必须以一种能够被快速、并行访问的方式排列。错误的内存布局会导致严重的性能下降，例如“缓存未命中”和“内存带宽浪费”。
> - **访问模式**：不同的资源有不同的访问模式，因此需要不同的布局来优化这些模式。

## Buffer 内存布局

Buffer（缓冲区）可以看作 GPU 上一段**线性的、未经解释的字节数组**。

1. **核心特征**：**简单**、**线性**
2. **布局比喻**：就像一本**没有任何格式的纯文本文档**，数据一个接一个地紧密排列。
    - 如：一个存储 `vec3` 位置数据的顶点缓冲区，它的布局可能就是：`[x1, y1, z1, x2, y2, z2, x3, y3, z3, ...]`。
    - 一个存储模型-视图-投影矩阵的常量缓冲区，可能就是：`[m00, m01, m02, m03, m10, ...]`。
3. **访问方式**：
    - 通过**字节偏移量** 来访问。
    - 在 Shader 中，你通过一个索引或一个基地址加上偏移量来获取特定位置的数据。
    - 例如，在 HLSL 中：`Vertex v = vertexBuffer[vertexId];`。
4. **对齐要求**：
    - 虽然 Buffer 本身是线性的，但为了 GPU 访问效率，其中的数据元素（尤其是常量缓冲区中的数据）通常需要满足特定的**字节对齐**要求（例如 16 字节对齐）。
    - 开发者需要手动处理填充以满足这些要求。
5. **主要用途**：
    - 顶点缓冲区（Vertex Buffer）
    - 索引缓冲区（Index Buffer）
    - 常量缓冲区（Constant Buffer）
    - 结构化缓冲区（Structured Buffer）：在线性布局的基础上，增加了“结构”的概念，但整体仍然是线性的块。


## Texture 内存布局

Texture（纹理）的内存布局则要复杂得多，它是**优化后的、非线性的**，通常对开发者是**不透明**的。

1. **核心特征**：**复杂、优化特定访问模式、黑盒**
2. **布局比喻**：不像线性的书，而像一本**经过精心排版的杂志**，文字和图片可能不是按顺序排列的，而是**为了快速翻阅和查找**（例如，看到文字见图1时，能立刻在当页找到图1）而设计的。
3. **访问方式**：
    - 通过 UV 坐标或像素坐标来访问。
    - 在 Shader 中，你使用采样器（Sampler）通过纹理坐标来获取颜色值：`float4 color = myTexture.Sample(mySampler, uv);`。
4. **布局细节**：Texture 的布局是为了优化**二维空间局部性**访问。
    - **Tiling / Swizzling（平铺/混洗）**：Texture 布局的核心，GPU 不会简单地按行（Row-Major）存储纹理像素。相反，它将纹理分割成一个个小块（例如 4x4 或 8x8 的像素块），然后以特定的顺序将这些块排列在内存中。
        - **原因**：当一个 Shader 请求一个纹理像素时，它和它周围的像素（用于滤波，如双线性过滤）很可能会被同时用到。Tiling 布局确保了这些在空间上相邻的像素在内存物理地址上也彼此靠近。这极大地提高了缓存命中率，因为一次内存读取可以获取一整块相邻的数据，而不是在内存中跳跃式地读取。
    - **Mipmaps（多级渐远纹理）**：
        - 一个 Texture 资源通常包含多个 Mipmap 层级（原始尺寸，1/2尺寸，1/4尺寸...）。
        - 这些 Mipmap 在显存中的排列顺序也是由驱动和 GPU 硬件决定的，通常它们会被组织在一起，以便根据 LOD 快速找到对应的层级。
5. **开发者控制**：
    - 开发者通常**无法直接控制或知晓**纹理在内存中的确切布局，这是由 GPU 驱动和硬件自动完成的，以达成最佳性能。
    - 你只能通过 API（如 Vulkan 的 `VkImageLayout`）来**告知** GPU 你打算如何访问这个纹理（例如，作为拷贝目标、着色器只读、渲染附件等），GPU 驱动可能会据此选择不同的内存布局策略。
6. **主要用途**：
    - 图像、贴图
    - 法线贴图、粗糙度贴图等
    - 渲染目标（Render Target）
    - 存储纹理（Storage Texture）：可读写的纹理
