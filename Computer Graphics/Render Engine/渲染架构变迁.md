渲染架构演进本质上是不断解决 CPU 与 GPU 协同效率、渲染复杂度管理和内存带宽与容量矛盾的历史。

## 变迁历史

#### 1. 固定管线（约2000年前后）

**架构特征**：

- 图形API仍是固定功能管线（DirectX 7/8，OpenGL 1.x）。
    
- 引擎仅做薄封装，将 `SetRenderState`、`DrawPrimitive` 等调用组织成更易用的材质、网格对象。
    
- 渲染流程在代码里是顺序的、线性的，没有复杂多Pass管理。
    

**变革驱动力**：

- 硬件只能做固定顶点光照、单纹理等，渲染逻辑简单，薄封装已足够。
    
- 可编程着色器尚未普及，没有处理大量独立着色器变体的需求。
    

#### 2. 即时渲染模式（Immediate Mode，可编程管线前期至DX11时代）

这里“即时渲染”不是OpenGL 1.0的glBegin/glEnd，而是指**引擎按代码逻辑，直接、顺序地向图形驱动提交渲染命令，立即执行**的模式。

**架构特征**：

- 基于状态机（DX9/11，OpenGL）。每一帧代码串行设置着色器、纹理、混合状态，然后Draw，驱动在后台隐式管理资源同步。
    
- 材质系统、多Pass光照（如前向渲染多遍光）通过硬编码或简单循环组织。
    
- 资源绑定和状态切换散落在渲染逻辑各处，容易产生冗余状态切换。
    

**遇到的瓶颈与革新原因**：

- **CPU单线程瓶颈**：所有Draw调用必须由单一线程串行提交，而多核CPU已普及，驱动层的隐式锁争用进一步降低效率。
    
- **驱动开销爆炸**：状态验证、资源转换、隐式屏障完全由驱动猜测执行，Draw Call数量一旦上千就容易CPU bound。
    
- **多Pass管理混乱**：延迟渲染兴起后，G-Buffer、光照、后处理等十余个Pass，纹理间依赖、状态切换全靠程序员人为保证，极易出错且难以维护。
    
- **无法充分利用硬件**：移动端Tile-Based GPU（如PowerVR、Mali）需要明确知道Render Target的Load/Store操作才能避免反复读回主存；而桌面端GPU拥有异步计算、拷贝队列，却被隐式同步白白浪费。
    

这些痛点最终催生了新一代**显式图形API**（DX12、Vulkan、Metal），并带来了Render Pass与图形命令缓冲的强制显式化。

#### 3. Render Pass 模式（显式帧结构，随Vulkan/Metal/DX12诞生）

**架构特征**：

- **Render Pass 对象成为一等公民**：引擎必须预先声明该Pass涉及哪些附件（颜色、深度）、附件的加载/存储动作（Load/Clear/DontCare/Store），以及子通道（Subpass）之间的依赖关系。
    
- 渲染命令被录制到命令列表，而非直接提交，允许多线程并行构建命令。
    
- 资源状态转换（如 Shader Resource → Render Target）由应用显式插入屏障。
    

**解决了什么**：

- **移动GPU性能质变**：Render Pass的Load/Store语义让Tile-Based GPU可以把中间结果完全留在片上缓存，避免带宽浪费，功耗和性能收益巨大。
    
- **多线程命令录制**：可在不同线程独立录制不同Render Pass的命令，再串行提交，极大解放CPU。
    
- **资源过渡精确可控**：不再依赖驱动猜测，减少了不必要的流水线停顿。
    

**还未解决的问题**：

- 虽然单个Pass内已标准化，但**整个帧几十个Pass之间的资源生命周期、屏障插入、显存复用**仍然要靠手动管理，错误频发且难以全局优化。
    
- 随着渲染技术爆发（实时反射、阴影级联、SSAO、TAA、各种后处理、Ray Tracing），帧结构变得极其复杂，纯手工“连线”已成为不可能的维护任务。
    

#### 4. Render Graph 模式（图驱动的帧生成，现代标杆）

**架构特征**：

- 整帧的渲染被抽象为一个**有向无环图（DAG）**，节点是渲染Pass，边是资源（纹理、Buffer）的读写依赖。
    
- 引擎先声明所有Pass及输入输出资源，形成一个“惰性构建”的图，再编译、优化，最后执行。
    
- 代表：Frostbite 的 Frame Graph、虚幻引擎的 RDG（Render Dependency Graph）、Unity 的 Render Graph。
    

**核心革新原因**：

- **自动化资源生命周期与内存别名**：图分析可算出每个临时资源的有效区间，自动分配、复用显存块，使高峰显存用量下降30-50%。
    
- **自动屏障与状态转换**：根据依赖边推导所有必要的硬件屏障和资源布局转换，插入最优位置并合并，彻底杜绝手动错误。
    
- **无痛并行化**：图可以轻松识别没有依赖的Pass，将其命令录制作业分发到多线程并行完成。
    
- **动态Pass裁剪**：若某个Pass的输出最终不被画面引用，可直接剪除。比如某个阴影级联完全在视锥之外，可直接跳过。
    
- **异步计算融合**：在图中标出可在计算队列异步执行的Pass，系统自动插入跨队列同步，让图形和计算重叠。
