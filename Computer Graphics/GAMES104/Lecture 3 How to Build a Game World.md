游戏内的所有东西都被抽象为 Game Object（游戏对象），可以用面向对象的方式来表示，也可以用组件化的方式表示：
![](_imgs/Pasted%20image%2020251013094821.png)

现实世界的对象过于复杂，又没有明显的层级父子关系，所以往往使用组件化的方式进行表达，如一些现代化的游戏引擎中，
![](_imgs/Pasted%20image%2020251013095256.png)

让游戏世界动起来，就是要在一个时钟周期内（Tick）更新一遍游戏世界（一个时钟周期至少是 $1/30$ s，也就是每秒 30 帧，才能称为实时）。让游戏世界更新的顺序有基于对象的顺序，还有基于组件的方式，
![](_imgs/Pasted%20image%2020251013101322.png)

现代游戏引擎是按照按照 Component System 而更新，而不是按照每一个物体来更新。

游戏逻辑的交互可以硬编码到代码中，但是一般是使用事件机制进行交互，![](_imgs/Pasted%20image%2020251013101707.png)
空间上的数据管理是场景管理的核心，一般是通过游戏对象的唯一 ID，以及该对象对应的位置信息 Position 组件。为了提升效率，往往对场景进行层级划分，常见的有网格，以及四叉树、八叉树等。
