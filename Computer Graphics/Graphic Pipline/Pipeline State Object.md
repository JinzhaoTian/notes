Pipeline State Object（管线状态对象，PSO）是现代图形 API（如 Direct3D 12、Vulkan、Metal）中的一个核心概念。

PSO 是在 GPU 开始执行绘制或计算命令之前，预先将所有渲染或计算管线的配置状态打包成一个不可变（或低开销可变）的对象。

> [!tip] 为什么需要 PSO？
> 在旧的图形 API（如 OpenGL、Direct3D 11）中，设置渲染管线状态是通过大量独立的函数调用完成的：
> 
> - 设置着色器代码
> - 设置顶点布局
> - 开启深度测试
> - 设置混合模式
> - 设置光栅化模式
> - ...
> 
> 这些状态**在每次绘制时**都会被驱动层实时验证、编译和组装，导致大量的 CPU 开销和驱动开销，这是传统 API 的痛点。

## 工作原理

在新的 API 中，你将所有影响图形或计算管线的状态**提前组合成一个不可变对象**（即 PSO）。创建 PSO 时，驱动已经完成了所有验证、编译和硬件指令生成。到了渲染帧的关键循环中，你只需要切换不同的 PSO，GPU 就能快速加载对应的硬件配置。

## 包含内容

一个典型的图形 PSO 包含：

| 类别          | 具体配置                       |
| ----------- | -------------------------- |
| **着色器**     | 顶点、像素、几何、计算、域、外壳着色器的编译后代码  |
| **顶点布局**    | 顶点数据的排列方式（位置、法线、UV 的位置和格式） |
| **混合状态**    | 颜色如何与帧缓冲区中已有颜色进行混合（透明效果等）  |
| **光栅化状态**   | 面剔除模式、多边形填充模式（线框/实体）、深度偏移  |
| **深度/模板状态** | 深度测试/写入是否开启、比较函数、模板操作      |
| **渲染目标格式**  | 颜色缓冲区、深度缓冲区的格式和多重采样样本数     |

## 主要优点

- **低 CPU 开销**：渲染时只需绑定一个对象，而不是调用几十个状态设置函数。
- **提前优化**：驱动可以在创建时（而非运行时）做大量优化和预编译。
- **多线程友好**：可以在后台线程预先创建各种 PSO，不阻塞渲染主线程。
- **可预测性**：管线状态固定，GPU 更容易调度和执行。

## 使用流程

```cpp
// 初始化阶段：创建 PSO
PSODesc desc;
desc.shaderVS = loadCompiledShader("vertex.cso");
desc.shaderPS = loadCompiledShader("pixel.cso");
desc.blendMode = BLEND_ALPHA;
desc.depthTest = true;
pso = device->createPipelineStateObject(desc);

// 每一帧：渲染循环
commandList->setPipelineState(pso);   // 一次调用，全部配置生效
commandList->drawIndexed(...);
```


## PSO 的变体与计算

- **图形 PSO**：用于渲染网格、几何体。
- **计算 PSO**：用于 Compute Shader（通用计算），包含的内容更少（主要是着色器代码和根签名）。
- **PSO 变体**：由于不同材质往往需要不同的 PSO（如无光照、一个光源、多个光源），引擎通常会维护一个 PSO 缓存来复用。

> [!tip] 与根签名（Root Signature，D3D12 概念）的关系
> - **PSO** 定义 **“GPU 应该做什么”**（着色器、各种测试、混合）。
> - **根签名** 定义 **“GPU 从哪里读取数据”**（常量缓冲、纹理、描述符堆）。
