开源许可证主要分为两大类：宽松型许可证（Permissive Licenses）和 Copyleft 许可证，它们在代码使用、修改、分发及衍生作品的要求上有显著差异。

## Permissive Licenses

### MIT License

- **特点**：最宽松的许可证之一，允许任意使用、修改和分发，包括商业用途，仅需保留原始版权声明。
- **适用场景**：个人项目、商业软件、教学示例（如 React、Node.js ）。
- **注意事项**：无专利保护条款，若贡献者起诉专利侵权，MIT不提供保护。

### Apache License 2.0

- **特点**：类似 MIT，但额外提供明确的专利授权，防止专利诉讼；要求保留 NOTICE 文件（记录版权和专利信息）。
- **适用场景**：企业级项目（如 Hadoop、Kafka ），需专利保护时优先选择。
- **注意事项**：与 GPLv3 不兼容，混用可能导致法律冲突。

### BSD License

- **变体**：2-Clause（简化版）和 3-Clause（新增“禁止用作者名推广”条款）。
- **特点**：允许闭源商用，仅需保留版权声明；3-Clause 禁止未经许可使用原作者名义宣传。
- **适用场景**：学术研究、商业集成（如 FreeBSD、OpenSSH）。

### ISC License

- **特点**：与 MIT / BSD 类似，但更简洁，常见于网络和系统软件。

### Unlicense / CC0

- **特点**：放弃所有版权，将代码置入公共领域，允许无限制使用。
- **适用场景**：希望完全放弃权利的项目（如SQLite）



## Copyleft Licenses

这类许可证要求衍生作品必须保持开源，具有“传染性”，确保代码自由共享。

### GPL

GPL（GNU General Public License）：
- **特点**：强 Copyleft，任何衍生作品必须以 GPL 发布，且必须公开源代码（如 Linux 内核）。
- **版本差异**：GPLv3 增加专利和反 DRM 条款，与 Apache 2.0 不兼容。
- **适用场景**：强调开源共享的核心项目。

### LGPL

LGPL（GNU Lesser General Public License）
- **特点**：弱 Copyleft，允许动态链接到闭源软件，但修改的库代码仍需开源（如 GNU C 库）。
- **适用场景**：库开发，平衡开源与商业使用。

### AGPL

AGPL（Affero GPL）
- **特点**：比GPL更严格，要求网络服务（如 SaaS）也必须公开源代码（如 GitLab ）。

### MPL

MPL（Mozilla Public License）
- **特点**：文件级 Copyleft，仅要求修改的文件开源，其他部分可闭源（如 Firefox ）。

### EPL

EPL（Eclipse Public License）
- **特点**：类似 MPL，但更适用于大型协作项目（如 Eclipse IDE）



## 其他类型

- **SSPL（Server Side Public License）**：由 MongoDB 创建，要求云服务商开源相关代码，争议较大，未被 OSI 认可为开源协议。
- **木兰协议（Mulan PSL）**：中国开源协议，类似 Apache 2.0，强调中文社区友好（如OpenEuler）
