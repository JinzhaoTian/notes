
> [!info]
> 在[面向对象编程](../Language/Programming%20Paradigm/面向对象编程.md)中，有一条非常经典的设计原则是：**组合优于继承**，多用组合少用继承。

## 继承

继承（Inheritance）的核心是 is-a 的关系，基于另一个已有的类（基类）定义一个类（派生类），
- 派生类自动获得基类的所有属性（成员变量） 和行为（方法），**除了私有成员**
- 派生类可以：
    - **直接使用**继承来的属性和方法
    - **覆盖（Override）** 继承来的方法，提供自己的特定实现
    - **扩展**功能，添加自己新的属性和方法

继承的目的是实现代码复用、建立类之间的层次关系（分类体系）、支持多态性（通过父类引用指向子类对象）。


## 组合

组合（Composition）的核心是 has-a 的关系，允许一个类（整体类）包含另一个类（部分类）的实例作为其成员变量，
- 整体类不直接继承部分类的行为，而是**持有**一个或多个**部分类**对象的**引用**。
- 整体类通过调用它所持有的**部分类**对象的**公有方法**来委托任务或利用其功能。
- 部分类的实现细节对整体类是隐藏的，两者通过定义清晰的接口进行交互。

组合的目的是实现代码复用（通过包含功能对象）、构建更灵活和松散耦合的系统、避免继承的局限性（如单继承限制、脆弱基类问题）。


## 组合优于继承

组合优于继承是面向对象设计（OOD）中的一个**基本原则**，强调在设计类之间的关系时，**优先考虑使用组合，只在真正符合 is-a 关系且继承能带来显著好处时才使用继承**。

### 原因

1. **更强的封装性与更低的耦合度**：
	- **组合**：
		- 整体类通过部分类的**公有接口**与其交互，整体类不需要知道部分类的内部实现细节。
		- 只要接口不变，部分类的内部修改不会影响整体类。
		- 耦合度低。
	- **继承**：
		- 子类通常可以直接访问父类的受保护成员，甚至通过某些方式访问私有成员（如反射）。
		- 子类对父类的实现细节有很强的依赖和了解。
		- 父类的内部实现变更（即使是私有方法）可能无意中破坏子类。
		- 继承带来了模块间的最强耦合性。

2. **更大的灵活性**：
	- **组合**：
		- 可以在**运行时**动态地改变部分对象，只要它们实现了相同的接口，这使得行为更容易改变和扩展。
	- **继承**：
		- 关系在编译时就固定了（静态绑定），一旦一个类继承自另一个类，这个关系在运行时就不能改变，改变行为通常需要创建新的子类。

3. **避免层级爆炸和菱形继承问题**：
	- **组合**：
		- 可以通过组合多个不同的类来实现所需功能，不会导致复杂的类层次结构。
	- **继承**：
		- 当需要复用多个来源的功能时，如果只依赖继承（特别是在只支持单继承的语言如 Java 中），会导致层级爆炸或者菱形继承问题。

> [!info] 层级爆炸
> 创建大量中间类来组合不同维度的功能，使得类层次结构变得庞大、复杂且难以理解。

> [!info] 菱形继承 
> 在支持多继承的语言（如 C++ ）中，如果一个类 D 同时继承自类 B 和类 C ，而 B 和 C 又都继承自类 A ，那么 D 中会包含两份 A 的成员，导致歧义。
> 
> 虽然可以通过虚继承解决，但增加了复杂性。

> [!info] 虚继承
> 虚基类用 virtual 声明继承关系，解决了菱形继承中派生类多个基类内存拷贝的问题，并没有解决多重继承的二义性问题。

4. **更符合单一职责原则**：
	- **组合**：
		- 鼓励将系统分解为更小、更专注的类（每个类负责单一职责），然后通过组合这些类来构建更复杂的对象。
		- 整体类的职责是协调其组成部分。
	- **继承**：
		- 容易导致子类承担过多的职责，因为它继承了父类的所有功能（即使它只需要一部分），并且还可能添加自己的新功能。
		- 这违反了单一职责原则，使得类难以维护和理解。

5. **打破单继承限制**：
    - **组合：** 
	    - 一个类可以轻松地组合（拥有）来自多个不同类的对象实例，不受语言单继承的限制。
    - **继承**：
	    - 在单继承语言中，一个类只能直接继承自一个父类。
	    - 如果需要复用多个类的功能，只能通过多层继承或接口（但接口只提供契约，不提供实现），灵活性受限。

6. **更易于测试**：
	- **组合**：
		- 可以轻松地为整体类的部分类成员创建模拟对象（Mock）或测试桩（Stub）进行单元测试，因为依赖是通过接口**注入**的。
	- **继承**：
		- 测试子类通常需要构建或模拟其父类的状态和行为，测试更复杂、耦合度更高。



## 继承更优的场景

1. **明确的 is-a 关系**：当两个类之间的关系非常清晰且稳定地符合子类是父类的一种特殊类型时（例如：Circle 是一个 Shape，SavingsAccount 是一个 Account）。
2. **需要多态行为**：当需要利用面向对象的核心特性多态，即通过父类接口统一处理不同的子类对象时，继承是实现多态最自然的方式。
3. **框架和库的设计**：框架经常定义基础类（如 `Exception`，`Thread`），期望用户通过继承来扩展和定制特定行为，继承提供了一种标准化的扩展点。
4. **共享接口和契约**：接口继承（在 Java / C# 等语言中通过 `implements` ）是定义契约和多态的关键手段，不涉及实现继承的问题，通常被积极鼓励。
