支付系统的[幂等性](../../Backend/API%20Design/幂等性.md)设计是确保同一笔交易无论被重复提交多少次，最终结果都保持一致的关键机制。

### 设计策略

#### 1. 唯一标识符机制

**实现方式**：
- 客户端在发起支付请求时生成唯一请求 ID（如 UUID 或业务唯一键）
- 服务端建立请求 ID 与处理结果的映射关系表

**示例**：
```sql
CREATE TABLE payment_idempotency (
    request_id VARCHAR(64) PRIMARY KEY,
    payment_id VARCHAR(64),
    status VARCHAR(32),
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

#### 2. 状态机控制

**实现方式**：
- 定义清晰的支付状态流转图（如：初始化→处理中→成功/失败）
- 确保状态转换是单向且不可逆的
- 在状态变更时进行校验

**状态检查伪代码**：
```java
public PaymentResult processPayment(PaymentRequest request) {
    Payment payment = paymentRepository.findByRequestId(request.getRequestId());
    
    if (payment != null) {
        return new PaymentResult(payment.getStatus(), payment.getPaymentId());
    }
    
    // 新建支付记录
    payment = createNewPayment(request);
    
    try {
        // 调用支付网关
        GatewayResponse response = paymentGateway.process(payment);
        
        // 更新支付状态
        payment.setStatus(response.isSuccess() ? "SUCCESS" : "FAILED");
        paymentRepository.update(payment);
        
        return new PaymentResult(payment.getStatus(), payment.getPaymentId());
    } catch (Exception e) {
        payment.setStatus("FAILED");
        paymentRepository.update(payment);
        throw e;
    }
}
```

#### 3. 数据库约束

**实现方式**：
- 在数据库层面设置唯一索引防止重复记录
- 使用乐观锁控制并发更新

**示例**：
```sql
-- 唯一索引
ALTER TABLE payments ADD UNIQUE INDEX idx_request_id (request_id);

-- 乐观锁更新
UPDATE payments 
SET status = 'SUCCESS', version = version + 1 
WHERE payment_id = '123' AND version = 1;
```

#### 4. 分布式锁机制

**实现方式**：
- 对关键操作使用分布式锁（如Redis锁）
- 锁粒度通常为业务ID或用户ID

**Redis锁示例**：
```java
public boolean tryLock(String lockKey, String requestId, long expireTime) {
    return redisTemplate.opsForValue().setIfAbsent(lockKey, requestId, expireTime, TimeUnit.MILLISECONDS);
}

public void unlock(String lockKey, String requestId) {
    if (requestId.equals(redisTemplate.opsForValue().get(lockKey))) {
        redisTemplate.delete(lockKey);
    }
}
```


### 实现方案

#### 1. 基于 Spring 的注解实现

```java
@Idempotent(
    key = "#request.requestId", 
    store = "redis", 
    expire = 3600
)
public PaymentResult processPayment(PaymentRequest request) {
    // 业务逻辑
}
```

#### 2. 基于 AOP 的通用处理

```java
@Aspect
@Component
public class IdempotentAspect {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Around("@annotation(idempotent)")
    public Object around(ProceedingJoinPoint joinPoint, Idempotent idempotent) throws Throwable {
        // 解析幂等键
        String key = parseKey(joinPoint, idempotent);
        
        // 检查是否已处理
        if (redisTemplate.opsForValue().get(key) != null) {
            return redisTemplate.opsForValue().get(key + "_result");
        }
        
        // 加锁
        boolean locked = tryLock(key);
        if (!locked) {
            throw new ConcurrentRequestException("请勿重复提交");
        }
        
        try {
            Object result = joinPoint.proceed();
            // 存储结果
            redisTemplate.opsForValue().set(key, "PROCESSED", idempotent.expire(), TimeUnit.SECONDS);
            redisTemplate.opsForValue().set(key + "_result", result, idempotent.expire(), TimeUnit.SECONDS);
            return result;
        } finally {
            unlock(key);
        }
    }
}
```


### 异常处理与补偿

1. **网络超时**：客户端应实现重试机制，携带相同 requestId
2. **系统崩溃**：通过定时任务扫描处理中的支付单，进行补偿处理
3. **对账机制**：定期与支付网关对账，修复不一致状态


### 最佳实践建议

1. 幂等键设计应包含业务标识（如用户ID+业务类型+业务ID）
2. 设置合理的幂等有效期（通常支付系统建议24小时）
3. 在高并发场景下，考虑使用本地缓存+分布式缓存的二级缓存机制
4. 提供明确的幂等错误码（如"重复请求"、"处理中"等）
5. 记录详细的幂等操作日志，便于排查问题
