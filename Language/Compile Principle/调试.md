程序调试机制是开发工具用于帮助开发者检测、诊断和修复代码错误（Bug）的核心功能。

### 调试器

**调试器（Debugger）**：作为调试工具的核心，通过与被调试程序（Debuggee）的交互实现控制。分为两类：
- **本地调试器**：直接与同一系统中的进程交互（如 [GDB](../C++/构建/GDB.md) 、LLDB ）。
- **远程调试器**：通过网络或协议与目标程序通信（如调试嵌入式设备时的 GDB Server ）。


### 程序控制机制

- **断点（Breakpoints）**：
    - **软件断点**：通过替换目标代码为调试指令（如 x86 的 `INT 3` ）触发中断。
    - **硬件断点**：利用 CPU 的调试寄存器（如 x86 的 DR0-DR3 ）直接监控地址访问。
    - **条件断点**：在断点触发时附加条件判断（如变量值变化时暂停）。

- **单步执行（Stepping）**：
    - **指令级单步**：依赖 CPU 的陷阱标志（如 x86 的 TF 标志），每条指令后触发中断。
    - **源码级单步**：通过符号表映射源码行与机器指令，控制执行流。


### 调试信息与符号表

- **调试格式**：编译器生成调试信息（如 DWARF 用于 Linux，PDB 用于 Windows ），包含：
    - 变量名、类型、作用域。
    - 源码行号与机器码的映射。
    - 函数调用约定和栈帧布局。

- **符号表**：将程序中的标识符（函数、变量）映射到内存地址，便于调试器解析。



### 进程控制接口

- **操作系统支持**：
    - **PTRACE（Linux）**：允许调试器读写目标进程内存、寄存器，并接收其状态变化通知。
    - **Windows Debug API**：提供 `WaitForDebugEvent` 、`ContinueDebugEvent` 等函数处理调试事件。

- **信号与异常处理**：调试器捕获目标进程的异常（如段错误），决定是否接管或传递。


### 状态检查与修改

- **寄存器/内存访问**：通过操作系统API或硬件接口直接读写目标进程的上下文。
- **变量监视（Watch）**：
    - **监视点**：利用硬件断点监控变量地址的读写。
    - **表达式求值**：在调试上下文中动态解析变量值（如调用 `eval` ）。


### 多线程/多进程调试

- **线程控制**：调试器跟踪所有线程状态，暂停/恢复时需协调所有线程。
- **子进程调试**：通过 `fork` 或 `CreateProcess` 标志（如 `DEBUG_ONLY_THIS_PROCESS` ）决定是否附加到子进程。


### 远程调试协议

- **协议标准**：如 GDB 远程串行协议（GDB Remote Serial Protocol），通过 TCP / UDP 传输调试命令。
- **存根（Stub）**：在目标端运行的轻量级服务，响应调试器的内存读写、断点设置等请求。
