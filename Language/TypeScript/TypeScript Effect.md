Effect 是一个用于结构化地管理程序中各类复杂问题的库（框架），提供了一套工具，帮你统一处理错误处理、异步逻辑、依赖注入和并发编程等问题。

| 特点        | 常规 TypeScript 写法                                         | 使用 Effect 库的写法                                                                                      |
| --------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **错误处理**  | 主要靠 `try/catch`，但错误信息不会体现在函数类型中，容易遗漏处理。                  | 错误被当作"值"处理，并且**明确写在类型签名** `Effect<Success, Error, Requirements>` 的 `Error` 位置，强制你处理或追踪它。            |
| **异步/并发** | 使用 `Promise` 和 `async/await`。对于复杂的并发、重试、超时等场景，需要自己写很多逻辑。 | 提供 `Effect.gen` 等语法糖，写法与同步代码几乎一样。拥有像 `Effect.all`、`Effect.forEach` 这样强大的并发原语，以及 `Schedule` 等重试策略模块。 |
| **依赖管理**  | 通常手动传入参数或使用依赖注入框架，依赖关系不够透明。                              | 内置了强大的**依赖注入系统**（`Context` 和 `Layer` 模块），服务的依赖关系也被写在类型 `Requirements` 中，清晰可见且易于替换和测试。               |
| **资源安全**  | 需要自己确保资源（如文件句柄、网络连接）在使用后被正确释放，容易出错。                      | 提供 `Scope` 和 `Fiber` 模块，通过结构化并发和资源作用域管理，能自动保证资源安全，防止泄漏。                                             |

## 核心思想

Effect 的核心是一个强大的类型 `Effect<Success, Error, Requirements>`。它像一份"程序说明书"，清晰地告诉你这段程序执行后会有三种结果：
1. **Success（成功）**：返回一个什么类型的值。
2. **Error（失败）**：可能会产生哪种预期的错误。
3. **Requirements（依赖）**：执行这个程序需要什么外部环境或服务（比如数据库、HTTP客户端）。

通过这种方式，程序的各种行为（包括副作用）都被纳入类型系统，变得可预测、可组合。
