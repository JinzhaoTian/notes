Ninja 是一个专注于速度的构建系统（Build System），通常与高级项目生成工具（如 CMake、GN）配合使用，来编译 C++、C 或其他语言的代码。

## 核心概念

1. **工作流程**：“不是编译器”。
	- Ninja 本身不编译代码（不像 g++ 或 clang++），其首先读取一个构建清单（通常是 `build.ninja` 文件），然后根据这个清单，以最快的速度、最高的效率决定哪些文件需要重新编译，并调用相应的编译器、链接器等工具来执行这些任务。
2. **设计哲学**：“做最少的事，但要做到最快”。
    - **低层级（Low-level）**：Ninja 的构建文件不包含复杂的逻辑（如条件判断、循环）。它被设计得非常简单和直接，只描述文件之间的依赖关系和构建规则。
    - **专注于速度**：它的唯一目标就是尽可能快地启动进程（如编译器），并并行运行尽可能多的进程，以最大限度地利用多核 CPU。它的启动开销和决策开销都非常低。
3. **跨平台**：Ninja 本身是跨平台的（Windows, macOS, Linux），其生成的构建文件通常也是跨平台的，因为它依赖于生成它的元构建系统来处理平台差异。


## 速度优势

1. **极简的设计**：Ninja 的输入文件格式非常简单，解析速度极快。
2. **精确的依赖关系**：Ninja 严重依赖由编译器（如 GCC/Clang 的 `-MD -MF` 选项）生成的精确的头文件依赖关系。这确保了当头文件改变时，所有依赖它的源文件都会被正确重新编译，避免了 `make clean` 这种核弹式的解决方案。
3. **出色的并行化**：Ninja 默认就会以高度并行的方式运行构建任务，完美利用多核处理器。其任务调度算法就是为了最小化空闲 CPU 时间而设计的。


## 安装

### Windows

1. **直接下载二进制包**：
	- 下载 Ninja：从 Ninja 的 [GitHub Releases](https://github.com/ninja-build/ninja/releases) 页面下载
	- 解压到指定目录，如 `C:\program\ninja` 
	- 将目录路径添加到系统的 PATH 环境变量中


## 工作流程

Ninja 通常不直接手动编写，而是由**元构建系统（Meta Build System）**（如 CMake）来生成。

这个过程分为两步：
1. **生成阶段（Configure & Generate）**：
    - 运行 CMake，并指定 Ninja 作为 Generator：`cmake -G Ninja <path_to_source>`
    - CMake 会处理 `CMakeLists.txt` 文件，分析项目结构、依赖、编译选项等。
    - 最后，CMake 生成一个为你的项目量身定制的、极其高效的 `build.ninja` 文件和一个 `rules.ninja` 文件，这个文件包含了所有构建规则和依赖关系。

2. **构建阶段（Build）**：
    - 运行 `ninja` 命令。
    - Ninja 读取上一步生成的 `build.ninja` 文件。
    - 它根据文件的时间戳和依赖图，计算出需要重新编译的最小文件集合。
    - 然后，它以最大并行度调用编译器、链接器等工具来执行实际的构建工作。


## 使用示例

```bash
# 1. 在一个干净的构建目录中，使用 CMake 并指定 Ninja 作为生成器
mkdir build
cd build
cmake -G Ninja ..

# 2. 使用 ninja 命令进行构建
ninja

# 你也可以指定并行编译的作业数（-j 参数），但 Ninja 默认已经做得很好了
# ninja -j 8

# 3. （可选）构建并运行测试
ninja test

# 4. （可选）安装（如果 CMake 配置了安装规则）
ninja install
```
