在 C++ 中，循环依赖通常指两个或多个**头文件**（`.h` 或 `.hpp`）相互直接或间接包含对方，导致编译器无法正确解析代码。这种问题常见于类之间相互引用时，会引发编译错误（如类型未定义、大小未知等）。

## 场景示例

```cpp
// A.h
#include "B.h"  // 包含 B 的头文件

class A {
    B* b_ptr;  // A 依赖 B
};
```

```cpp
// B.h
#include "A.h"  // 包含 A 的头文件

class B {
    A* a_ptr;  // B 依赖 A → 形成循环依赖！
};
```

此时编译器处理过程如下：
1. 编译 `A.h` 时，展开 `#include "B.h"`
2. 编译 `B.h` 时，又遇到 `#include "A.h"`
3. 由于头文件保护符（`#ifndef`）阻止重复包含，`A.h` 的内容被跳过
4. 当解析 `B` 类中的 `A* a_ptr` 时，`A` 尚未被定义 → **编译错误**

## 解决方案

### 方案一：前向声明

1. **使用前向声明（Forward Declaration）**：当类仅通过**指针/引用**（而非对象实例）依赖另一个类时，无需包含完整定义，只需前向声明。

```cpp
// A.h
class B;  // 前向声明（代替 #include "B.h"）

class A {
    B* b_ptr;  // 仅需指针 → 前向声明足够
};
```

```cpp
// B.h
class A;  // 前向声明（代替 #include "A.h"）

class B {
    A* a_ptr;  // 仅需指针 → 前向声明足够
};
```


2. **在实现文件（`.cpp`）中引入必要头文件**
```cpp
// A.cpp
#include "A.h"
#include "B.h"  // 在此处包含 B.h（实际需要 B 的定义时）

// 成员函数实现...
```

### 方案二：重构代码结构

- **提取公共依赖**：将共同依赖的部分移到独立头文件。
- **使用接口/纯虚类**：通过抽象基类解耦具体实现。


## 关键原则

1. **头文件尽量自包含**：通过前向声明减少包含依赖。
2. **避免在头文件中使用对象实例**：  
	- ✅允许：指针、引用、函数声明
    - ❌禁止：对象成员、继承、sizeof（需要完整定义）。
3. **使用头文件保护符**（防止重复包含）：
```cpp
#ifndef MY_HEADER_H
#define MY_HEADER_H
// 头文件内容
#endif
```


## 错误示例

若在头文件中声明对象成员（非指针）：
```cpp
// B.h
class A;  // 前向声明

class B {
    A a;  // 错误！需要 A 的完整定义（编译器无法确定 sizeof(A)）
};
```
