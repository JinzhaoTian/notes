
## 编译过程
![](../_imgs/Pasted%20image%2020230703154558.png)
1. `hello.c -> hello.i`： **预编译**，对应命令：`gcc –E` 。
	1. 预编译：读取c源程序，对其中的伪指令（以# 开头的指令）和特殊符号进行处理。
	2. 经过预编译得到的输出文件中，只有常量，如数字、字符串、变量的定义，以及C语言的关键字。
2.  `hello.i -> hello.s`：**编译**，对应命令：`gcc –S`。
	1. 编译：通过词法分析和语法分析，在确认所有的指令都符合语法规则之后，将其翻译成等价的中间代码表示或汇编代码。
	2. 优化处理是编译系统中一项比较艰深的技术。
3. `hello.s -> hello.o`：**汇编**，对应命令：`gcc -c`。
	1. 汇编：汇编语言代码翻译成目标机器指令的过程。
	2. 目标文件中所存放的也就是与源程序等效的目标的机器语言代码。目标文件由段组成。通常一个目标文件中至少有两个段，代码段、数据段。
4. `hello.o -> exe`：**链接**，对应命令：`gcc`。
	1. 链接：汇编程序生成的目标文件并不能立即就被执行，还需处理源文件对另外文件的引用问题。
	2. 链接处理可分为两种：静态链接、动态链接



## 链接库

在应用中，有些公共代码需要反复使用，于是就将这一部分代码编译成**库**文件。在链接步骤中，链接器将从库文件中取得所需要的代码，复制到生成的可执行文件中，该库文件即**静态链接库**（Static Link Library），其特点是可执行文件中包含一份库代码的完整拷贝，缺点就是被多次使用就会多份冗余拷贝。

在程序运行开始后，调用库函数时才被载入的库文件即**动态链接库**（Dynamic Link Library），该库独立于现有的程序，其本身不可执行，但包含着程序需要调用的一些函数。

在 Windows 平台下，静态链接库是 `.lib` 文件，动态链接库是 `.dll` 文件。在 Linux 平台下，静态链接库是 `.a` 文件，动态链接库是 `.so` （Shared Object）文件。

> 感觉这样分的理由是编译器的设置不同。


`libassimp.dll.a` 是一个 **导入库**（Import Library），用于在编译时将动态链接库（DLL）中的符号链接到你的应用程序，对应的实际的动态链接库是 `assimp.dll` ，包含 Assimp 的实现代码。在运行时，你的程序将加载 `assimp.dll` 以使用其中的功能。它通常出现在使用 MinGW-w64 或其他类似工具链编译中。
