1995 年 5 月，Brendan Eich 在 Netscape 内部完成的一个可运行引擎原型（Mocha），而不是今天我们所知的 JavaScript 1.0 的全部。据 Eich 本人回忆，这个原型是在 1995 年 5 月 6 日至 15 日之间完成的，他本人说过过：“引擎原型花了 5 月的十天”。

> [!quote] 被强加的“像 Java”约束
> Eich 最初被 Netscape 招募时的兴趣和计划，是将 Scheme 这样的函数式语言嵌入浏览器。然而，Netscape 与 Sun 的联盟改变了方向。
> 
> > [!info] Schema 编程语言
> > Scheme 编程语言诞生于 1970 年代（由 Gerald Jay Sussman 和 Guy L. Steele Jr. 等人设计）属于 Lisp 方言，受 Lambda 演算和早期 Lisp 影响，以极简语法和强大的函数式编程能力著称。
> > 
> > 在 Scheme 中，**一等函数**（first-class functions）指的是：**函数（更准确说是过程 procedure）和数字、字符串、列表一样，是一种“一等值”**。它可以出现在任何普通值能出现的位置。
> 
> Eich 后来回忆说，他当时处于“市场命令”之下：语言必须“看起来像 Java，但不能大到僭越”，需要成为一种“傻乎乎的小兄弟语言”。具体而言，他被禁止使用 Java 那种基于类的面向对象语法。这个约束**直接决定了 JavaScript 底层形态的走向**：**既然不能用 `class`，他就必须找到另一种实现对象和复用的方式**。
> 
> 在无法使用类语法的前提下，Eich 将多种来源的思想压缩进了一个最小可运行模型中：
> - **语法外观**：借鉴 C 语言的基本语法，包括花括号、分号和保留字，以满足“看起来熟悉”的要求。
> - **对象模型**：将 C 的 struct、Smalltalk 的模式，以及 LISP 中数据与代码的对称性结合起来。最关键的选择是采用 Self 语言的原型（**prototype**）继承，以此替代 Java/C++ 的类继承。
> - **一等函数**：尽管 Scheme 的整体方案被放弃，但其一等函数的思想被保留了下来，成为 JavaScript 函数作为值传递、被存储和组合的基础。
> - **事件模型**：灵感来自 HyperCard，用于将事件绑定到 HTML 文档上。
> 
> > [!info] Self 实验性编程语言
> > Self 是一门诞生于 20 世纪 80 年代的实验性编程语言，它并非为了成为主流商业语言而设计，而是作为一项深入探索面向对象编程（OOP）本质的研究项目。它在编程语言发展史上占有独特地位，是基于原型（Prototype-based） 这一 OOP 范式的纯粹典范，并深刻影响了后来的 JavaScript 等语言。
> > 
> > Self 用原型（`prototype`）和槽（`slot`）替代了传统的“类”与“实例”的二分结构。
> > - **对象即原型（`prototype`）**：在 Self 中，没有“类”作为模板。你通过复制（clone）一个已存在的“原型对象”来创建新对象，然后对其进行修改。每个对象都是独特且具体的个体。
> > - **对象由槽（`slot`）构成**：一个对象本质上是一个 `slot` 的集合，可以将其理解为一种更统一的属性或方法定义，`slot` 主要分为几种类型：
> > 	- **数据槽**：存储状态，类似于传统 OOP 中的实例变量。
> > 	- **方法槽**：包含行为代码。
> > 	- **父槽**（Parent Slot）：指向其他对象，实现行为委托与共享，这是 Self 的继承机制。
> > - **状态与行为统一**：在 Self 中，数据和方法都只是 `slot`，没有本质区别。这使得普通对象、过程（Procedure）和闭包（Closure）之间的界限变得模糊，概念上更为统一。
> 
> 1995 年剩余的时间和整个 1996 年，Eich 的工作重心是**浏览器集成**（即后来被称为 DOM Level 0 的部分），以及引擎的持续修补。1996 年，他还抽出时间重写了引擎，将原型中的部分实现替换为带有**垃圾回收**和**标记值**的 SpiderMonkey 架构。

1996 年 3 月，公开的 JavaScript 1.0 随 Netscape Navigator 2.0 发布，而第一个被 Eich 称为完整的版本则在 1996 年 8 月才出现。

> [!quote] 从 Mocha 到 JavaScript：命名的商业逻辑
> 这个语言在 Netscape 内部的代号是 Mocha，在 1995 年 9 月，随着 Netscape Navigator 2.0 的 Beta 版发布，它被更名为 LiveScript。在 1995 年 12 月，Netscape 与 Sun 联合宣布将其命名为 JavaScript。这次命名的动机是明确的商业考量：当时 Java 是炙手可热的技术，将新语言命名为“Java”的某种“脚本”形式，意在借势营销，将其定位为 Java 在网页端的轻量搭档。

1996 年，微软在 IE 3.0 中推出了自己的实现 JScript。由于 “JavaScript” 是 Netscape 与 Sun 的商标，微软无法直接使用该名称，但 JScript 在功能上模仿了 JavaScript，这意味着 Web 开发者面临两个行为可能不一致的实现。

为了阻止微软以自己的方言主导脚本语言，Netscape 于 1996 年 11 月将 JavaScript 提交给 Ecma International 进行标准化。标准化工作面临一个命名难题：不能使用 “JavaScript”（商标归属 Sun），也不能偏向 “JScript”（微软的方言）。最终，各方妥协采用了 ECMAScript 这个中性名称，对应的规范编号为 ECMA-262。第一版 ECMAScript 标准于 1997 年 6 月被 Ecma 大会采纳。从那时起，“JavaScript”作为语言的事实名称继续被广泛使用，而“ECMAScript”则成为其标准化规范的名字。

> [!quote] “乱”的根源：一部妥协的历史
> JavaScript 的混乱感，可以追溯到它诞生之初的几个关键事实：
> - **仓促的设计与过早的标准化**：JavaScript 最初仅用 10 天就完成了原型设计。其初衷只是处理简单的网页交互，并未预料到会用于构建大型应用。更关键的是，它在推出**一年半后**就被提交标准化（即 ECMA-262），许多设计缺陷在充分暴露之前就成了既定标准，调整的窗口期非常短。
> - **无法回头的历史包袱**：由于早期就被全球网页广泛采用，任何破坏性的修改都可能导致海量现有网站瘫痪。因此，**“向后兼容”** 成为了语言演进不可动摇的底线。这直接导致一些广为人知的“怪癖”被永久保留，例如 `typeof null` 返回 `'object'`，以及 `==` 运算符复杂的隐式类型转换规则等。
