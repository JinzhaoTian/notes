NativeAOT（Native Ahead-Of-Time）是 .NET 生态中的一种提前编译技术，其目标是将 .NET 代码（如 C# 代码）直接编译成一个真正的、不依赖 .NET 运行时的本地可执行文件，这个可执行文件是特定于目标操作系统（如 Windows、Linux、macOS）和 CPU 架构（如 x64, Arm64）的。

## .NET 运行流程

1. **编写代码**：用 C# 等语言编写代码。
2. **编译成 IL**：C# 编译器将代码编译成一种叫做 IL（中间语言） 的字节码，并打包到一个 `.dll` 或 `.exe` 的程序集中，**这个程序集并不是真正的本地代码，它只是一个引导程序**。
3. **JIT 编译**：当用户运行这个程序时，.NET 运行时（CLR） 会被加载。在方法第一次被调用时，JIT（Just-In-Time，即时）编译器会将 IL 代码实时地编译成本地机器码，然后执行。

### 优点

- 跨平台（编写一次，到处运行），灵活的运行时优化（可以根据当前机器的 CPU 进行特定优化）。

### 缺点

- **启动速度慢**：因为 JIT 编译发生在运行时。
- **内存占用高**：需要加载整个运行时和 JIT 编译器。
- **依赖运行时**：目标机器上必须安装相应版本的 .NET 运行时。


## NativeAOT 工作流程

1. **编写代码**：用 C# 等语言编写代码。
2. **编译成 IL**：同样编译成 IL 程序集。
3. **提前编译**：在**开发者构建应用的时候**，NativeAOT 编译器（基于 ILC 工具链）会：
    - 分析你的所有代码和依赖项。
    - 执行类似 JIT 的编译过程，但这是在**构建阶段**完成的。
    - 将 IL 代码**直接编译**成目标平台的高效本地机器码。
    - 生成一个**自包含的、独立的本地可执行文件**。


### 优点

- **极快的启动速度**：因为所有代码在运行前已经是本地机器码，无需 JIT 编译。
- **更低的内存占用**：不包含 JIT 编译器和大量运行时组件。
- **更小的部署尺寸**：通过剪裁功能，只包含你实际用到的代码，可以生成非常小的可执行文件。
- **无运行时依赖**：用户可以直接运行生成的可执行文件，无需安装 .NET 运行时。这类似于 Go 或 Rust 编译出的程序。

### 缺点

- **失去运行时灵活性**：无法进行基于当前运行环境的 JIT 优化。
- **编译时间更长**：构建过程更复杂，耗时更长。
- **反射和动态代码的局限性**：由于是静态编译，严重依赖反射、动态加载、Emit 等技术的库可能无法正常工作或需要特殊处理。这是最大的兼容性挑战。
