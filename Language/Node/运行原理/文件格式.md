
## `*.cjs`

**`.cjs`** 文件是 Node.js 中用于表示 CommonJS 的文件扩展名。


## `*.mjs`

**`.mjs`** 文件是 Node.js 中用于表示 ES Module（ECMAScript Module） 的文件扩展名。简单来说，它就是明确告诉 Node.js：“这个文件要按 ES6 模块规范来解析”。

### 核心作用

Node.js 早期只支持 CommonJS（`require` / `module.exports`），后来才加入对 ES Module（`import`/ `export`）的支持。为了让两种模块系统共存且不冲突，Node.js 用扩展名来区分：

| 扩展名    | 模块系统                             | 语法                           |
| ------ | -------------------------------- | ---------------------------- |
| `.js`  | 取决于 `package.json` 的 `"type"` 字段 | 可能是 CJS，也可能是 ESM             |
| `.cjs` | 强制 CommonJS                      | `require` / `module.exports` |
| `.mjs` | 强制 ES Module                     | `import` / `export`          |

所以 `.mjs` 的最大意义是：**无论 `package.json` 怎么配置，这个文件一定按 ES Module 处理。**

> [!caution] Node.js 的历史包袱
> Node.js 无法只靠文件内容判断一个 `.js` 文件到底是 CJS 还是 ESM。于是它定了个规矩：`.js` 文件默认还是 CJS，除非在 `package.json` 里声明 `"type": "module"`。
> 
> 但这个规矩带来了麻烦：
> - **项目迁移不灵活**：一个老项目想把个别文件改成 ESM，不能单独改，得动整个项目的配置。
> - **工具脚本很尴尬**：像 `vite.config.js` 这种独立的工具脚本，经常没有配套的 `package.json`，想用 ESM 语法写，只能叫 `.mjs`。


### 常见场景

`.mjs` 文件常见于执行脚本：
- **工具配置文件**：像 `vite.config.mjs`、`rollup.config.mjs`，这类独立工具通常不依赖宿主项目的 `package.json` 配置，用 `.mjs` 最直接。
- **Node.js CLI 工具**：很多 npm 包的可执行文件（`bin`）会命名为 `cli.mjs`，以确保无论用户项目怎么配置，它都能作为 ESM 正确运行。
- **云函数入口**：比如 AWS Lambda 就推荐用 `index.mjs` 作为入口，以启用 ESM 支持。
- **依赖包内部**：一些现代库（如 Angular）在发布时，会专门生成 `.mjs` 版本供打包工具使用。
