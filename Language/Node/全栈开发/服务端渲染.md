服务端渲染（Server-Side Rendering, SSR）是一种**在服务器端生成完整的 HTML 页面**并将其发送给客户端的渲染技术。在这种渲染方式中，服务器接收到客户端的请求后，会执行后端代码（如处理数据查询或应用逻辑），然后将页面的 HTML 内容渲染好，再将完整的 HTML 发送给客户端。客户端只需解析和显示 HTML 页面，而不需要再进行额外的 JavaScript 渲染。


## 客户端渲染

客户端渲染（Client-Side Rendering，CSR）通常由 JavaScript 在浏览器端生成和渲染页面内容，适合单页应用（SPA），页面的初始加载时间可能较长，但后续交互体验更加流畅。



## 服务端渲染

### 特点

- SEO友好：由于服务器已经渲染好了完整的 HTML 页面，搜索引擎的爬虫可以很容易地抓取页面内容，因此 SSR 对于 SEO（搜索引擎优化）非常有利。
- 首屏加载快：服务器直接返回渲染好的页面，用户首次访问时页面可以更快显示，减少白屏时间。
- 减少客户端计算：客户端不需要做太多复杂的计算，尤其对于不支持 JavaScript 或性能较低的设备更友好。

### 缺点

- 服务器压力大：每次请求都需要服务器渲染和生成 HTML 页面，这会增加服务器的负载，尤其是高并发情况下。

- 交互体验稍弱：与客户端渲染（Client-Side Rendering，CSR）相比，SSR 页面在首次加载后，用户的交互体验和响应性会稍微逊色，特别是在需要大量交互的应用中。

### 服务端渲染框架

- Next.js（React 生态）：支持服务端渲染的 React 框架。
- Nuxt.js（Vue 生态）：支持服务端渲染的 Vue 框架。
- Django、Ruby on Rails 等传统的 Web 框架也提供服务端渲染功能。
